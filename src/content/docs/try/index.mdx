Here you combine apps built with juiz to drive a mobile robot in a simulator.
You do not write or build any code. You download published `.juizapp` packages and start them with a double-click.

1. Drive the robot with a keyboard or a gamepad,
2. build a map of the room from its LiDAR and odometry with **SLAM** (Simultaneous Localization and Mapping: estimating the robot's own position and building a map at the same time),
3. and finally let the robot drive itself to a goal on that map (**autonomous navigation**).

While the [tutorial](/tutorial/) teaches the features of juiz one at a time, this section lets you run finished apps and see how the whole system fits together. You can start before finishing the tutorial.

<Aside type="tip" title="What you will see">
- Separately distributed juiz apps becoming one robot system, connected by topics and IDs
- Odometry (the position computed from wheel rotation) drifting more and more, and SLAM and localization correcting it by matching against the map
- Coordinate frames (Transformations) forming a single tree across separate apps
- What is streamed on topics (sensor readings, velocity commands) and what is called over HTTP (goals, paths, maps)
</Aside>

## Apps and setup

All the apps are published by OpenJUIZ. All but navigation_manager are `.juizapp` packages.

The screens of these apps are in Japanese. These pages give the English meaning of the labels you need.

<Steps>

1. Install the `juiz` command and navigation_manager with pip ([Installation](/getting-started/install/#installing-the-juiz-command) shows how to make a venv).

   ```sh
   pip install juiz-cli==0.3.0 navigation-manager==0.3.5
   ```

   This gives you two commands, `juiz` and `navigation-manager`.
   mapper_gmapping and localization_amcl are C++ apps whose packages say `juiz: "=0.3.0"`, so they start only with juiz 0.3.0. Use exactly these versions.

2. Make `.juizapp` files start on a double-click. If you installed into a venv, run this once in a terminal with that venv active.

   ```sh
   juiz associate
   ```

   See [Installation: Opening .juizapp files with a double-click](/getting-started/install/#opening-juizapp-files-with-a-double-click) for details.

3. Make a working folder `try_juiz`. You put the downloaded `.juizapp` files, and the map you build on page 2, here.

## Starting an app

Start a `.juizapp` by double-clicking the file.

A double-click opens a new terminal window and runs `juiz run` in it. The window title becomes `juiz - <app name> <version>`.
The app runs only while this window is open. To stop it, close the window or press Ctrl+C in it.

<Aside type="note" title="The first double-click on macOS">
macOS asks whether "JUIZ Launcher" may control Terminal. Allow it.
</Aside>

### When it starts (OK)

For mobile_sim, the window shows the following and stays there (the path depends on your machine).

```text
Running mobile_sim 0.3.6 from /home/you/.cache/juiz/apps/mobile_sim-0.3.6-fd2fb57c16789ce6
Close this window or press Ctrl+C to stop.
juiz 管理画面: http://localhost:8000/ui/
IPC broker: ipc://mobile_sim
HTTP broker: http://127.0.0.1:8000/
```

It is OK when you see `HTTP broker: http://127.0.0.1:<port>/`, no line starting with `error:`, and the window stays open. `<port>` is the port in the URL under each app name in the table above. (`管理画面` means *web UI*.)
Each page shows what that app prints when it is OK.

### When it does not start (NG)

- **A line starting with `error:` and then `Press Enter to close.`**: the start failed. Read the error, then press Enter to close the window. Common ones:

  | Message | Cause and fix |
  | --- | --- |
  | `error: mobile_sim is already running at ipc://mobile_sim.` | The same app is already running. Find the window you opened before, or close it and start again |
  | `error: mapper_gmapping 0.4.3 requires juiz =0.3.0, but this is juiz 0.2.11.` | The juiz version does not match. Reinstall with the version in step 1 (`juiz-cli==0.3.0`), then run `juiz associate` again (the file may be associated with the juiz of another venv) |

- **`depends on mobile_sim ... but it is not running` and a numbered choice**: the app needs mobile_sim, which is not running. Double-click mobile_sim first, then type the number of `retry` in this window and press Enter.
  ```text
  teleop_twist depends on mobile_sim >=0.3.1, <0.4, but it is not running at ipc://mobile_sim.
    1) enter where mobile_sim is (ex., http://192.168.0.10:8100)
    2) retry
    3) quit
  choose [1]:
  ```
- **A window flashes and disappears, nothing happens, another app (such as an archive tool) opens the file, or the OS asks how to open it**: `.juizapp` is not associated with juiz.
  - If the `juiz` command is not installed, start over from [Installation: Installing the juiz command](/getting-started/install/#installing-the-juiz-command).
  - If it is, run `juiz associate` as in [Installation: Opening .juizapp files with a double-click](/getting-started/install/#opening-juizapp-files-with-a-double-click). [Guide: Starting by double-click](/guides/app-package/#starting-by-double-click) has the differences between operating systems.

<Aside type="tip" title="You can also start from a terminal">
Instead of a double-click, you can run `juiz run mobile_sim-0.3.6.juizapp` in a terminal opened in `try_juiz`. It prints the same (except the `Close this window ...` line). Press Ctrl+C to stop.
</Aside>
