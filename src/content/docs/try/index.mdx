Here you combine apps built with juiz to drive a mobile robot in a simulator.
You do not write or build any code. You download published `.juizapp` packages and start them with `juiz run`.

1. Drive the robot with a keyboard or a gamepad,
2. build a map of the room from its LiDAR and odometry with **SLAM** (Simultaneous Localization and Mapping: estimating the robot's own position and building a map at the same time),
3. and finally let the robot drive itself to a goal on that map (**autonomous navigation**).

While the [tutorial](/tutorial/) teaches the features of juiz one at a time, this section lets you run finished apps and see how the whole system fits together. You can start before finishing the tutorial.

<Aside type="tip" title="What you will see">
- Separately distributed juiz apps becoming one robot system, connected by topics and IDs
- Odometry (the position computed from wheel rotation) drifting more and more, and SLAM and localization correcting it by matching against the map
- Coordinate frames (Transformations) forming a single tree across separate apps
- What is streamed on topics (sensor readings, velocity commands) and what is called over HTTP (goals, paths, maps)
</Aside>

## The apps

All of them are published by OpenJUIZ. All but navigation_manager are `.juizapp` packages.

| App | Role | Screen |
| --- | --- | --- |
| mobile_sim | A simulator of a mobile robot on a plane. Publishes LiDAR scans and odometry | http://localhost:8000/ |
| teleop_twist | Reads a keyboard or a gamepad in the browser and publishes velocity commands | http://localhost:8002/ |
| mapper_gmapping | Estimates a map and the robot's position from scans and odometry with GMapping | http://localhost:8001/ |
| localization_amcl | Estimates the robot's position on a map with AMCL (a particle filter) | http://localhost:8002/ |
| planner_dijkstra | Finds the route to the goal (the global path) with Dijkstra's algorithm | http://localhost:8003/ |
| planner_dwa | Computes velocity commands that follow the global path and avoid obstacles, with DWA | http://localhost:8004/ |
| navigation_hub | Puts the navigation apps into one tree and relays topics | http://localhost:8006/ |
| navigation_manager | Takes a goal, has a path planned and followed, and decides when the robot has arrived (Python, installed with pip) | http://localhost:8005/ |

teleop_twist and localization_amcl both use port 8002, so you swap them between the first half (pages 1–3) and the second half (pages 4–6).

The screens of these apps are in Japanese. These pages give the English meaning of the labels you need.

## Setup

1. Install the `juiz` command and navigation_manager with pip.

   ```sh
   pip install juiz-cli==0.2.11 navigation-manager==0.3.4
   ```

   This gives you two commands, `juiz` and `navigation-manager`.
   mapper_gmapping 0.4.2 and localization_amcl 0.1.3 are C++ apps whose packages say `juiz: "=0.2.11"`, so they start only with juiz 0.2.11. Use exactly these versions.

   ```sh
   mkdir try_juiz
   ```

### Checking the SHA-256

These are the SHA-256 hashes of the seven files. Save this content in the working directory as a file named `SHA256SUMS`.

```text title="SHA256SUMS"
f14a4d4a511ddae7520d0e361a34d1d9060b38bf87c08e7aaf3104584c4725fc  planner_dwa-0.1.2.juizapp

```

Then check them with this command.

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
sha256sum -c SHA256SUMS
```

</TabItem>
<TabItem label="macOS">

```sh
shasum -a 256 -c SHA256SUMS
```

</TabItem>
<TabItem label="Windows">

```powershell
Get-Content SHA256SUMS | ForEach-Object {
    $hash, $file = $_ -split '\s+'
    if ((Get-FileHash $file -Algorithm SHA256).Hash -eq $hash) { "${file}: OK" } else { "${file}: FAILED" }
}
```

</TabItem>
</Tabs>

If all seven lines say `OK`, you are fine. Delete any file that says `FAILED` and download it again.

<Aside type="note" title="Where these values come from">
The Releases do not include a checksum file such as `SHA256SUMS`.
The values above are the same SHA-256 that GitHub shows next to each file on the Release page (follow the "Release" links in the table).
When you download a newer version, compare against the values on that version's Release page.

`juiz run` also checks, when it unpacks a package, that the files inside match the SHA-256 listed in its `juizapp.yaml`. That only tells you the contents of the package are complete; whether the package itself has been replaced is what the check on this page tells you.
</Aside>
