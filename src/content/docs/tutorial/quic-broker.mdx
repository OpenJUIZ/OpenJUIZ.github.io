In chapter 6 you connected separately started juiz instances through the HTTP broker.
In juiz, the part that talks to other juiz instances and outside programs is called a **broker**, and you choose brokers in the configuration file.
In this chapter you connect the talker and the listener as in chapter 6, but through the QUIC broker instead of HTTP.

<Aside type="tip" title="What you will learn">
- The transport is chosen as a broker, without changing the Process code
- The start of an ID (`http://` or `qmp://`) tells which broker the request goes through
- One juiz can run several brokers at the same time
</Aside>

<Aside type="caution" title="Requires juiz 0.0.18 or later">
Since juiz 0.0.18, the QUIC broker is built into the `juiz` command. It works as is whether you installed `juiz` with `cargo install juiz_app` or with pip (`juiz-cli`).
Check the version with `cargo install --list` or `pip show juiz-cli`, not `juiz --version`. With 0.0.17 and earlier, you have to build the QUIC broker from the juiz source and load it as a plugin.
</Aside>

## What is the QUIC broker?

QUIC is a transport that runs over UDP and carries several exchanges in parallel inside one encrypted connection.
The juiz QUIC broker sends data over QUIC encoded as MessagePack. Its broker type name is `qmp` (QUIC + MessagePack).

Compared with the HTTP broker:

| | HTTP broker | QUIC broker |
| --- | --- | --- |
| Type name (start of the ID) | `http` | `qmp` |
| Port | 8000 (TCP; 8001, 8002, … if in use) | Set in the configuration file (UDP; startup fails if in use) |
| Data format | JSON | MessagePack |
| Use from outside tools | Callable from Swagger UI or curl | Used between juiz instances |
| Included in `juiz` | Built in | Built in (0.0.18 and later) |

<Aside type="note">
The QUIC broker creates a self-signed certificate each time it starts, and the connecting side does not verify certificates. Traffic is encrypted, but the peer's identity is not checked, so use it inside a network you trust.
It can only send values such as numbers and strings; it cannot send images.
</Aside>

## Prepare the configuration files

The QUIC broker is built into the `juiz` command, so you only need to list it under `brokers` in the configuration file to instantiate it.
Create the following two files at the root of the example repository. They are the same for every language.

`listener_qmp.conf`, for the listener, makes the QUIC broker listen on UDP port 5000.

```yaml
name: listener_qmp
brokers:
  - type_name: qmp
    name: qmp0
    port: 5000
```

`talker_qmp.conf`, for the talker, differs only in its name and port. Unlike the HTTP broker, the QUIC broker does not move to another port when its port is in use; juiz fails to start instead. Give each juiz its own port number.

```yaml
name: talker_qmp
brokers:
  - type_name: qmp
    name: qmp0
    port: 5001
```

The `name` under `brokers` is required, but any name will do.

The commands you type in terminal 3 can also send requests to `qmp://` IDs as they are. They need no configuration file.

## Start the listener

As in chapter 6, this chapter uses three terminals. Open each of them at the root of the example repository (for Python, activate the venv in every terminal).

In terminal 1, start the listener. It is the chapter 6 command with `-f listener_qmp.conf` added.


## Connect over QUIC

In terminal 3, connect the talker's output to the listener's argument `arg1`. Just replace the IDs in the chapter 6 command with `qmp://` IDs.

<Tabs syncKey="lang">
<TabItem label="Rust">

```sh
juiz connection create -t push \
  "qmp://127.0.0.1:5001/process/talker0::talker" \
  arg1 \
  "qmp://127.0.0.1:5000/process/listener0::listener"
```

</TabItem>
<TabItem label="Python">

```sh
juiz connection create -t push \
  "qmp://127.0.0.1:5001/process/talker_python0::talker_python" \
  arg1 \
  "qmp://127.0.0.1:5000/process/listener_python0::listener_python"
```

</TabItem>
<TabItem label="C++">

```sh
juiz connection create -t push \
  "qmp://127.0.0.1:5001/process/talker_cpp0::talker_cpp" \
  arg1 \
  "qmp://127.0.0.1:5000/process/listener_cpp0::listener_cpp"
```

</TabItem>
</Tabs>

The listener in terminal 1 starts printing. Ask the talker side, which holds the connection, and you can see that the destination is a `qmp://` ID.

<TabItem label="Rust">


</TabItem>
<TabItem label="Python">

</TabItem>

The talker's juiz sees that the destination ID starts with `qmp://` and delivers the values to the listener over QUIC.

## Call over QUIC

Calls work the same way. With a `qmp://` ID, the call goes through the QUIC broker.

<Tabs syncKey="lang">
<TabItem label="Rust">

```sh
juiz process call "qmp://127.0.0.1:5001/process/talker0::talker" '{}' -p
# => CapsulePtr((value:Value("Hello World"), option: []))
```

</TabItem>
<TabItem label="Python">

```sh
juiz process call "qmp://127.0.0.1:5001/process/talker_python0::talker_python" '{}' -p
# => CapsulePtr((value:Value("Hello, World!"), option: []))
```

</TabItem>
<TabItem label="C++">

```sh
juiz process call "qmp://127.0.0.1:5001/process/talker_cpp0::talker_cpp" '{}' -p
# => CapsulePtr((value:Value("Hello, Juiz!"), option: []))
```

</TabItem>
</Tabs>

## Try it yourself

- Add the same `brokers` as in `talker_qmp.conf` to `talker_ec.conf` from chapter 6 and start it. Find the EC's ID with `juiz -s qmp://127.0.0.1:5001 ec list`, and start it with `juiz -s qmp://127.0.0.1:5001 ec start <ID>`.
- Connect again with only the destination changed to the `http://127.0.0.1:8000/...` ID. The listener's juiz runs both brokers, so the values arrive through either ID.
- Send `juiz -s qmp://127.0.0.1:5002 process list` to a port nobody listens on. QUIC runs over UDP, so the failure is not noticed right away; after a while you get the error `connecting to qmp broker '127.0.0.1:5002' (127.0.0.1:5002) timed out`.

## Summary

- The communication part of juiz is a broker. Besides the HTTP broker, you can choose the QUIC broker (`qmp`). Both are built into the `juiz` command and instantiated under `brokers` in the configuration file.
- The start of an ID (`http://` or `qmp://`) tells which broker a request goes through. `juiz connection create` and `juiz process call` use QUIC just by changing the ID.
- One juiz can run several brokers at the same time. The same Process has one ID per broker.
- A Process's code does not know which broker calls it. That is why the Process works unchanged when you change the transport.
- To pass images and other large data quickly to another process on the same machine, there is also the IPC broker (`ipc`, juiz 0.1.0 or later). See [Choosing a broker and large data](/guides/large-data/) for when to use which.
