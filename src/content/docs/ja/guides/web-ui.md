juiz には、動いている系(System)の中身をブラウザで確かめる管理画面が入っています。
HTTP ブローカーを有効にして起動すれば、追加のインストールなしで `/ui/` を開くだけで使えます。
今は表示だけの段階で、接続の作成や `p_apply` などの操作は画面からはできません。

![管理画面。左に系のツリー、中央にシステム図、右に選んだ Process の性質が並ぶ](../../../../assets/web-ui/overview.png)

:::caution[juiz 0.0.19 以降が必要です]
管理画面は juiz 0.0.19 から `juiz` コマンドに入っています。`cargo install juiz_app` で入れた場合も、pip の `juiz-cli` で入れた場合も、ビルド済みの画面が入っているので Node.js は要りません。
:::

## 開く

HTTP ブローカーを有効にして juiz を起動します。`-d` で起動すると、HTTP ブローカーが 8000 番で立ち上がります。

```sh
juiz -f increment_process.conf -d
# => juiz 管理画面: http://localhost:8000/ui/
```

起動時に表示される URL をブラウザで開きます。画面と API は同じ juiz から配信されるので、CORS の設定は要りません。
別のマシンで動いている juiz なら、`http://<そのマシンのアドレス>:8000/ui/` を開きます。

画面は 4 つの部分でできています。

| 場所 | 内容 |
|---|---|
| 上部の帯 | 接続先、状態(接続中 / 未接続)、更新間隔、最終更新の時刻、「更新」ボタン |
| 左のツリー | 系とその中の要素の一覧 |
| 中央の図 | 系の要素と接続を描いたシステム図 |
| 右の性質欄 | 選んだ要素の詳しい中身 |

画面の用語は日本語の漢字を正とし、API やこのサイトで使う英語名を小さく並べて書いています。

| 画面の用語 | このサイトでの名前 |
|---|---|
| 系 | System |
| 副系 | Subsystem(別プロセスの juiz) |
| 処理 | Process |
| 容器 | Container |
| 容器処理 | ContainerProcess |
| 実行文脈 | ExecutionContext(EC) |
| 接続 | Connection |
| 話題 | Topic |
| 仲介 | Broker |
| 生成器 | Factory |

## 左のツリーと性質欄

左のツリーは、系 → 処理・容器(その下に容器処理)・実行文脈・接続・話題・仲介 → 各要素 の順に並びます。分類や要素の ▸ / ▾ で畳めます。
要素を押すと、右の性質欄にその要素の中身が出ます。

| 種類 | 性質欄に出るもの |
|---|---|
| 処理・容器処理 | 型、識別子、説明、言語、生成器、所属する容器、引数(名前・型・既定値)、入力と出力の接続、対象にしている実行文脈、発行・購読する話題 |
| 容器 | 型、識別子、説明、言語、生成器、引数、容器処理 |
| 実行文脈 | 型、識別子、状態(停止中 / 実行中)、周期、自動開始、対象の処理 |
| 接続 | 押込(Push)・引込(Pull)、送り元、送り先と引数、識別子 |
| 話題 | 発行する処理、購読する処理と引数 |
| 仲介 | 型、識別子 |
| 系 | 経由する仲介、UUID、仲介、要素の数 |

性質欄の中の要素名を押すと、その要素に移ります。
引数表の「拘束値」(`p_apply` で与えた値)と「戻値型」は、まだ表示できず「—」「不明」と出ます。

juiz に接続できなくなると、上部の状態が「未接続」になり、ツリーの上に理由が出ます。前回取れた内容は薄く表示したまま残ります。

## システム図の見方

中央の図は、系の要素を種類ごとの形と色で描きます。

| 要素 | 図 |
|---|---|
| 処理 | 緑の楕円 |
| 容器 | 水色の長方形。容器処理(緑の楕円)は容器の外に置き、容器から水色の線で結ぶ(処理側の端が白丸) |
| 実行文脈 | 黄色の長方形。「停止中」「実行中」の枠のうち今の状態が光り、実行中なら対象の処理へ黄色の矢印が出る |
| 話題 | マゼンタの長方形。処理 → 話題が赤の矢印(発行)、話題 → 処理がマゼンタの矢印(購読) |
| 接続 | 処理 → 処理の矢印。押込は実線、引込は破線。矢印の先に引数名 |

線の種類は図の左下の凡例にも出ています。

- 配置は左から右へのデータの流れになるよう自動で決まります。要素や線の顔ぶれが変わったときだけ配置し直します。
- 要素はドラッグで動かせます。位置はブラウザに接続先ごとに保存されます。
- 図の右上の「自動配置」で保存した位置を消して自動配置に戻し、「全体」で全体が見える倍率にします。
- 要素や接続の線を押すと選ばれ、ツリーと性質欄にも同じものが出ます(ツリーで選んだときも図の中で選ばれます)。選んだ処理には照準の輪が重なり、輪の左に引数ごと、右に出力の弧が出ます。つながっているものが光ります。

## 別プロセスの juiz を表示する

[第6章 別々のプロセスをつなぐ](/ja/tutorial/multi-process/) のように、2 つ目の juiz が 1 つ目の juiz のサブシステムとして登録されていると、1 つ目の juiz の管理画面に 2 つ目の中身も出ます。
たとえば listener を 8000 番、talker を 8001 番で起動して talker → listener をつないだあと、`http://localhost:8000/ui/` を開くと次のようになります。

![副系の表示。副系 127.0.0.1:8001 の talker0 から、系 localhost:8000 の listener0 へ矢印が枠をまたいでいる](../../../../assets/web-ui/subsystem.png)

- 左のツリーでは、副系は系の「副系」の下に入れ子で出ます。経由する仲介(`http`、`qmp` など)が名前の横に出ます。中身を取れなかった副系には「取得不可」と出ます。
- 図では、副系があるときだけ系ごとに破線の枠で囲みます。別の系どうしの接続は枠をまたぐ矢印になります。枠の見出しを押すと、その系が選ばれます。
- 接続は、出す側の処理がいる系の下に出ます。両方の系から見える接続も 1 本にまとめます。

QUIC ブローカー([第7章](/ja/tutorial/quic-broker/))で登録した副系も、同じように表示されます。

## 設定

左のツリーの上にある「設定」ボタンから変えます。値はブラウザに保存されます。

| 項目 | 内容 |
|---|---|
| 接続先 | 空なら画面を開いた juiz。別の juiz を指すと、その juiz 側に CORS の設定が要ります(下の「別の場所から開くとき」) |
| 更新間隔(秒) | 自動更新の間隔。既定は 2 秒、最短 0.5 秒。0 以下にすると自動更新しなくなり、上部の「更新」ボタンを押したときだけ更新します |

## juiz 側の設定

### 配信を止める

管理画面を配信したくないときは、設定ファイルの `option.http_broker` で `webui: false` にします。

```yaml
option:
  http_broker:
    start: true
    port: 8000
    webui: false
```

### 別の場所から開くとき(CORS)

画面を、見たい juiz とは別のオリジン(別のホストやポート)から開くときは、見たい juiz の側で CORS を許可します。`option.http_broker.cors_allow_origins` に許可するオリジンを並べます(既定では許可しません)。

```yaml
option:
  http_broker:
    start: true
    port: 8000
    cors_allow_origins:
      - "http://localhost:8001"
```

`"*"` と書くとどこからでも呼べるようになるので、手元で試すときだけにしてください。

### 自分でビルドした画面を配信する

画面のソースは juiz リポジトリの [`webui/`](https://github.com/OpenJUIZ/juiz/tree/main/webui) にあります。ビルドした画面を `option.http_broker.static_filepaths` の `/ui` に指定すると、埋め込みの画面の代わりにそちらを配信します。パスは juiz を起動したディレクトリからの相対です。

```yaml
option:
  http_broker:
    start: true
    port: 8000
    static_filepaths:
      /ui: "./webui/dist"
```

画面の開発の仕方は [webui/README.md](https://github.com/OpenJUIZ/juiz/blob/main/webui/README.md) を見てください。
