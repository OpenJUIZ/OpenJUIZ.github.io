import { Tabs, TabItem, Aside } from '@astrojs/starlight/components';

Process・Container・Component を作り始めるときのプロジェクトを、コマンド 1 つで作れます。

```sh
juiz pkg create my_robot -b rust
```

作った雛形は、手を加えずにビルド → `juiz -f app/app.conf` で起動 → 呼び出し → `juiz pack` で [.juizapp](../app-package/) にして配布、まで通ります。
ビルドのファイルに書く SDK(juiz_sdk・pyjuiz・libjuiz_sdk・hsjuiz・zigjuiz)の版は、雛形を作った juiz 自身の版にそろえて書かれます。チュートリアルでつまずきやすい「`juiz --version` と同じ版にそろえる」を手で直す必要はありません。

<Aside type="caution" title="juiz 0.2.6 以降が必要です">
`juiz pkg` は juiz 0.2.6 から使えます。`juiz --version` で確かめてください。`pip install juiz-cli` で入れた juiz にも、`cargo install juiz_app` で入れた juiz にも入っています。
</Aside>

<Aside type="tip" title="チュートリアルとの関係">
[チュートリアル](../../tutorial/)の第 1〜3 章は、この雛形(`-t process` で作り、第 2 章で `juiz pkg add container` で Container を足す)を使って進めます。雛形の中のファイルの読み方は、チュートリアルの第 1 章で説明しています。
</Aside>

## 作る

```sh
juiz pkg create <名前> -b <言語> [-t <種類>] [-o <ディレクトリ>]
```

| オプション | 既定 | 意味 |
| --- | --- | --- |
| `<名前>` | (必須) | 英小文字で始まり、英小文字・数字・`_` だけの名前(`my_robot` など)。Component の名前、パッケージ名、型名の頭になります |
| `-b`, `--lang` | (必須) | `rust` / `python` / `cpp` / `haskell` / `zig` |
| `-t`, `--template` | `component` | 入れる型の種類。`component` / `process` / `container`(下の表) |
| `--idl <file.jidl>` | なし | 例の型の代わりに、JIDL の宣言から型付きの関数を作ります([下](#jidl-から型付きの雛形を作るidl)) |
| `-d`, `--design <juizdesign.yaml>` | なし | 設計文書から雛形を作ります([下](#設計文書から雛形を作るcreate--d))。`<名前>`・`-t`・`--idl` の代わりに使います |
| `-o`, `--output` | `./<名前>` | 作るディレクトリ。既にあって空でなければエラーになり、何も書きません |
| `--license` | `none` | `mit-apache` で LICENSE-MIT・LICENSE-APACHE を置き、各ファイルのライセンスの欄に `MIT OR Apache-2.0` を書きます |
| `--author` | `git config user.name` | `--license mit-apache` のときの著作権者 |
| `--juiz-sdk-dir` | `~/.juiz/sdk/<版>` | C++・Haskell・Zig のみ。libjuiz_sdk を置いた場所 |
| `--hsjuiz-dir` | `~/juiz-<版>/bindings/hsjuiz` | Haskell のみ。hsjuiz のソースの場所 |
| `--zigjuiz-dir` | なし | Zig のみ。zigjuiz のソースの場所。指定すると `build.zig.zon` にそこへの相対パスを書きます。指定しなければ、`scripts/dev.sh` が初回に Releases から `zig fetch` で取り込みます |

名前の規則に合わないときは、直した名前の例を添えたエラーになります(`My-Robot` なら `my_robot` など)。言語のキーワード(`type`・`class` など)や `juiz`・`std`・`test` なども使えません。

### 入る型

どの種類でも、作るのは 1 つの Component です。種類で変わるのは、その中に入る型だけです。名前が `my_robot` のとき:

| 型 | 種類 | 引数(既定値) | 戻り値 | 働き | 入る `-t` |
| --- | --- | --- | --- | --- | --- |
| `my_robot_add` | Process | `a: int`(0)、`b: int`(0) | int | `a + b` を返す | `component`・`process` |
| `my_robot` | Container | `initial_value: int`(0) | — | 整数 `value` を 1 つ持つ | `component`・`container` |
| `my_robot_increment` | ContainerProcess | `step: int`(1) | int | `value += step` して `value` を返す | `component`・`container` |
| `my_robot_get` | ContainerProcess(readonly) | なし | int | `value` を返す | `component`・`container` |

引数と戻り値には型が付いているので、[管理画面](../web-ui/)の呼び出しフォームや、接続するときの型の検査がそのまま効きます。

### 中身

`-b rust` の例です。

```text
my_robot/
├─ Cargo.toml              ビルドのファイル(言語ごと)
├─ src/lib.rs              Component のソース(言語ごと)
├─ app/
│  ├─ app.conf             起動する設定ファイル。.juizapp の entry
│  └─ juizapp.yaml         .juizapp のマニフェスト
├─ scripts/
│  ├─ dev.sh   dev.ps1     ビルドしてプラグインを app/plugins/<ターゲット>/ に置く
│  └─ pack.sh  pack.ps1    dist/my_robot-0.1.0.juizapp を作る
├─ juizdesign.yaml         設計文書。入っている型を言語によらない形で書いたもの([下](#設計文書juizdesignyaml))
├─ README.md               この雛形の使い方(英語)
└─ .gitignore
```

| 言語 | ビルドのファイル | Component のソース | scripts |
| --- | --- | --- | --- |
| Rust | `Cargo.toml` | `src/lib.rs` | `dev`・`pack`(`.sh`・`.ps1`) |
| Python | `pyproject.toml` | `app/python/<名前>.py` | `pack` だけ(ビルドが無いため) |
| C++ | `CMakeLists.txt` | `src/<名前>.cpp` | `dev`・`pack`(`.sh`・`.ps1`) |
| Haskell | `cabal.project`、`<名前-kebab>.cabal` | `src/<Name>.hs` | `dev.sh`・`pack.sh`・`bundle-plugin-deps.sh` |
| Zig | `build.zig`、`build.zig.zon` | `src/<名前>.zig` | `dev.sh`・`pack.sh` |

`app/app.conf` には、入っている型のインスタンス(`my_robot_add0`、`my_robot0` など)と、`my_robot_increment0` を 1 秒ごとに呼ぶ実行コンテキスト `main_ec`(`auto_start: false` なので、起動しただけでは動きません)が書かれています。HTTP のポートは 8000 です。
雛形の中のコメントと README は英語です。

## ビルドして動かす

作ると、次に打つコマンドが表示されます(README.md にも同じものが書かれています)。言語ごとに、最初の準備だけが違います。

<Tabs syncKey="lang">
<TabItem label="Rust">

```sh
juiz pkg create my_robot -b rust
cd my_robot
scripts/dev.sh                  # cargo build して app/plugins/<ターゲット>/ に置く
juiz -f app/app.conf -d         # 起動(このままにしておく)
```

Windows では `scripts\dev.ps1` を使います。`scripts/dev.sh --release`(Windows は `-Release`)で release ビルドになります。

</TabItem>
<TabItem label="Python">

```sh
juiz pkg create my_robot -b python
cd my_robot
python3 -m venv .venv
. .venv/bin/activate
pip install -e .                # pyproject.toml の pyjuiz(juiz と同じ版)を入れる
juiz -f app/app.conf -d         # 起動(このままにしておく)
```

Windows では `python -m venv .venv`、`.venv\Scripts\activate` です。juiz を `pip install juiz-cli` で入れているなら、同じ venv に入れておくと簡単です。

</TabItem>
<TabItem label="C++">

```sh
juiz pkg create my_robot -b cpp
cd my_robot
# 初回だけ: libjuiz_sdk(juiz と同じ版)を ~/.juiz/sdk/<版> に置く
curl -fsSL https://raw.githubusercontent.com/OpenJUIZ/juiz/main/scripts/install-juiz-sdk.sh | sh -s -- 0.3.5
scripts/dev.sh                  # cmake でビルドし、プラグインと libjuiz_sdk を app/plugins/<ターゲット>/ に置く
juiz -f app/app.conf -d         # 起動(このままにしておく)
```

cmake と C++ コンパイラが要ります。Windows では `install-juiz-sdk.ps1` と `scripts\dev.ps1` を使います(手順は [インストール](../../getting-started/install/) の C++ を見てください)。
`juiz pkg create` は SDK が無いときに入れるコマンドを表示するので、`0.3.5` の所はその表示のとおりにしてください。

</TabItem>
<TabItem label="Haskell">

```sh
juiz pkg create my_robot -b haskell
cd my_robot
# 初回だけ: hsjuiz のソースと libjuiz_sdk(どちらも juiz と同じ版)を用意する
git clone --depth 1 --branch v0.3.5 https://github.com/OpenJUIZ/juiz.git ~/juiz-0.3.5
curl -fsSL https://raw.githubusercontent.com/OpenJUIZ/juiz/main/scripts/install-juiz-sdk.sh | sh -s -- 0.3.5
scripts/dev.sh                  # cabal build して app/plugins/<ターゲット>/ に置く
juiz -f app/app.conf -d         # 起動(このままにしておく)
```

ghc と cabal が要ります。`cabal.project` には hsjuiz と libjuiz_sdk の場所が絶対パスで書かれます。用意してから作っても、作ってから用意してもかまいません(無ければ、作るときに警告と用意するコマンドが表示されます)。
Haskell は Linux と macOS だけです(Windows では雛形は作れますが、動かせません)。

</TabItem>
<TabItem label="Zig">

```sh
juiz pkg create my_robot -b zig
cd my_robot
# 初回だけ: libjuiz_sdk(juiz と同じ版)を入れる
juiz sdk install
scripts/dev.sh                  # 初回は zigjuiz を zig fetch で取り込み、zig build して app/plugins/<ターゲット>/ に置く
juiz -f app/app.conf -d         # 起動(このままにしておく)
```

Zig 0.17.x が要ります(`pip install ziglang==0.17.1` で入れたときは `ZIG="python3 -m ziglang" scripts/dev.sh`)。名前は 32 文字までです(`build.zig.zon` の `.name` の制限)。
`scripts/dev.sh --target aarch64-unknown-linux-gnu` のように、別の CPU・OS 向けにもビルドできます(先に `juiz sdk install --target <ターゲット>`)。
Zig は juiz 0.3.3 から使えます。Windows では juiz 0.3.4 から、`scripts\dev.ps1`(`-Release`・`-Target`)と `scripts\pack.ps1` を使います。ターゲットは `x86_64-pc-windows-msvc` です([issue #588](https://github.com/OpenJUIZ/juiz/issues/588))。0.3.3 の Zig の雛形は Linux と macOS だけです。

</TabItem>
</Tabs>

別の端末から呼び出します。`my_robot_get` は `my_robot_increment` を呼んだ回数だけ増えた値を返します。

```sh
juiz process call "http://127.0.0.1:8000/process/my_robot_add0::my_robot_add" '{"a": 1, "b": 2}' -p
# => CapsulePtr((value:Value(3), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/my_robot_increment0::my_robot_increment:my_robot0" '{"step": 1}' -p
# => CapsulePtr((value:Value(1), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/my_robot_get0::my_robot_get:my_robot0" '{}' -p
# => CapsulePtr((value:Value(1), option: []))
```

ここから先は、Component のソースの関数を書き換え、型を足して(次の節)、自分の部品に育てていきます。

## 型を足す(juiz pkg add)

雛形の Component に、Process や Container を足せます。雛形のディレクトリで打ちます。

```sh
juiz pkg add process my_robot_sum         # Process my_robot_sum
juiz pkg add container my_robot_arm       # Container my_robot_arm と my_robot_arm_increment・my_robot_arm_get
```

| 引数 | 足す型 | 中身 |
| --- | --- | --- |
| `process <名前>` | Process `<名前>` | `my_robot_add` と同じ(`a + b`) |
| `container <名前>` | Container `<名前>`、ContainerProcess `<名前>_increment`・`<名前>_get` | `my_robot` などと同じ |

- 書き換えるのは **Component のソース 1 つと `app/app.conf`、設計文書 `juizdesign.yaml` だけ**です。新しいファイルは作らず、Cargo.toml・CMakeLists.txt・.cabal・build.zig も直しません。
- 言語と Component の名前は `app/app.conf` から読みます。別のディレクトリの雛形には `-C <ディレクトリ>` を付けます。
- 同じ名前が conf やソースに既にあればエラーになり、何も変えません。ソースの形を大きく変えていて足す場所が見つからないときも、エラーになって手で足すよう案内されます。
- README.md の型の表は直しません。

足した後は、ビルドのある言語では `scripts/dev.sh` でビルドし直し、juiz を起動し直します。打つコマンドは `juiz pkg add` が表示します。

## JIDL から型付きの雛形を作る(--idl)

[データ型](../datatype/)の JIDL に書いた `process`・`container` の宣言から、引数と戻り値に型の付いた関数を持つ雛形を作れます。Rust・Python・C++・Haskell・Zig の 5 つの言語で使えます(Python・C++・Haskell は 0.2.7 から、Zig は 0.3.3 から)。

```text
// arm.jidl
namespace my.arm;
import idl "juiz_std/geometry.jidl";

/** Move the arm tip to the target */
process juiz_std.geometry.Pose2D move_to(juiz_std.geometry.Pose2D target, double speed = 1.0);

container gripper {
  container_process boolean grip(double force = 1.0);
}
```

```sh
juiz pkg create my_arm -b rust --idl arm.jidl
```

どの言語でも、`idl/` に渡した .jidl(と import している .jidl)の写しが入り、`app/app.conf` には宣言の型ごとのインスタンス(move_to0、gripper0、grip0)が入ります。関数は `juiz idl -g <言語>-skeleton` と同じもので、本体はまだ書かれていません。本体を書く前に呼び出すと失敗します。言語ごとの違いは次のとおりです。

<Tabs syncKey="lang">
<TabItem label="Rust">

```text
my_arm/
├─ Cargo.toml        [build-dependencies] に juiz_idl。juiz_std の型を使うときは juiz_std_types も
├─ build.rs          idl/ の .jidl から Rust の型を作る
├─ idl/arm.jidl
├─ src/lib.rs        宣言ごとの関数。本体は todo!()
└─ app/app.conf
```

```rust
pub fn move_to(target: ::juiz_std_types::juiz_std::geometry::Pose2D, speed: f64) -> JuizResult<::juiz_std_types::juiz_std::geometry::Pose2D> {
    let _ = (target, speed);                    // 本体を書くときはこの 2 行を消す
    todo!("write the body of move_to")
}
```

型はビルドのたびに build.rs が作るので、.jidl を変えたら `scripts/dev.sh` でビルドし直すだけです。ContainerProcess は `&mut ContainerImpl<…>` で受けます。

</TabItem>
<TabItem label="Python">

```text
my_arm/
├─ idl/arm.jidl
├─ app/python/my_arm.py      宣言ごとの関数。本体は raise NotImplementedError
├─ app/python/my/arm/…       .jidl の型(作るときに書く)
└─ app/app.conf
```

```python
@juiz_process
def move_to(target: Pose2D, speed: float = 1.0) -> Pose2D:
    """Move the arm tip to the target"""
    raise NotImplementedError("write the body of move_to")
```

型は作るときに一度だけ書きます(juiz_std の型は pyjuiz に入っています)。.jidl を変えたら `juiz idl -g python --extern juiz_std -o app/python idl/arm.jidl` で作り直してください(README にも書いてあります)。

</TabItem>
<TabItem label="C++">

```text
my_arm/
├─ CMakeLists.txt    juiz_generate_types で idl/ の .jidl から型のヘッダを作る
├─ idl/arm.jidl
├─ src/my_arm.cpp    宣言ごとの関数。本体は throw std::runtime_error
└─ app/app.conf
```

```cpp
std::optional<::juiz_std::geometry::Pose2D> move_to(const ::juiz_std::geometry::Pose2D& target, double speed) {
    (void)target;
    (void)speed;
    throw std::runtime_error("write the body of move_to");
}
```

型のヘッダ `build/juiz_idl/juiz_idl.h` はビルドのたびに作られます。そのため、ビルドのときに `juiz` コマンドが PATH に要ります。

</TabItem>
<TabItem label="Haskell">

```text
my_arm/
├─ my-arm.cabal      hs-source-dirs に gen、other-modules に型のモジュール
├─ idl/arm.jidl
├─ src/MyArm.hs      宣言ごとの関数。本体は error "…"
├─ gen/              .jidl の型(scripts/dev.sh がビルドの前に作る。git には入れない)
└─ app/app.conf
```

`scripts/dev.sh` がビルドの前に `juiz idl -g haskell -o gen idl/arm.jidl` で型を作ります。.jidl に名前空間が増えたら、.cabal の `other-modules` に足してください。

</TabItem>
<TabItem label="Zig">

```text
my_arm/
├─ build.zig         juiz.addTypes で idl/ の .jidl から型を作り、juiz_types として渡す
├─ build.zig.zon
├─ idl/arm.jidl
├─ src/my_arm.zig    宣言ごとの関数。本体は return error.NotImplemented
└─ app/app.conf
```

```zig
fn move_to(args: struct { target: types.juiz_std.geometry.Pose2D, speed: f64 = 1.0 }) !types.juiz_std.geometry.Pose2D {
    _ = args;
    // write the body of move_to
    return error.NotImplemented;
}
```

型は `zig build` のたびに `juiz-idl -g zig`(無ければ `juiz idl -g zig`)で作られます。そのため、ビルドのときに `juiz` コマンドが PATH に要ります。

</TabItem>
</Tabs>

- `-t` とは一緒に使えません。例の型(`my_arm_add` など)は入りません。
- 宣言のある名前空間は 1 つにしてください(1 つの雛形は 1 つの Component です)。`juiz_std` は数えません。
- `import` する .jidl は、渡した .jidl と同じディレクトリかその下に置いてください。相対パスのまま `idl/` に写すためです。
- JIDL には状態の型を書けないので、Container の状態は空です。必要なものを自分で足してください。
- 呼び出しの例(作ったときの表示と README)の引数は、既定値か、型から作った値(数は 0、文字列は `""` など)です。
- 言語によっては作れない宣言があり、そのときはファイルを書く前にエラーになります。Python・C++ では `T?`・`bytes` の引数、Python では既定値のある引数の後ろに既定値のない record・enum の引数、Haskell では型のモジュール名が Component のモジュール名と同じになるとき(名前 `myrobot` と名前空間 `myrobot` など)です。

## 設計文書(juizdesign.yaml)

雛形の型(Process・Container・ContainerProcess の名前・引数・戻り値・Container の状態)は、言語によらない **設計文書** `juizdesign.yaml` に書かれています。juiz 0.3.5 から、`juiz pkg create` は雛形の直下にこの文書も置き、雛形のソースや `app/app.conf`・README の型の表もこの文書から作ります。

設計文書は、次の 3 つの使い方ができます。

| 使い方 | コマンド |
| --- | --- |
| 今までどおり雛形を作る(設計文書も一緒にできる) | `juiz pkg create <名前> -b <言語> [-t …\|--idl …]` |
| 設計文書だけを書く | `juiz pkg design <名前> [-t …\|--idl …] [-b <言語>] [-o <ファイル>]` |
| 設計文書から雛形を作る | `juiz pkg create -d <juizdesign.yaml> [-b <言語>] [-o <ディレクトリ>]` |

先に型を設計してから、その文書を雛形にするのが 2 つめと 3 つめの使い方です。同じ文書から別の言語の雛形も作れます。

<Aside type="caution" title="juiz 0.3.5 以降が必要です">
設計文書(`juiz pkg design`・`create -d`)は juiz 0.3.5 から使えます。0.3.4 までの juiz で作った雛形には `juizdesign.yaml` がありません。
</Aside>

### 文書の形

`juiz pkg design my_robot` で書かれる文書(`-t component` と同じ型)です。

```yaml title="juizdesign.yaml"
# yaml-language-server: $schema=https://raw.githubusercontent.com/OpenJUIZ/juiz/v0.3.5/juiz_pkg/schema/juizdesign.schema.json
# my_robot: design of the juiz component my_robot (juiz docs/spec/design.md)
#   check:    juiz pkg design check juizdesign.yaml
#   scaffold: juiz pkg create -d juizdesign.yaml -b <rust|python|cpp|haskell|zig>
format: 1
component:
  name: my_robot
  description: "my_robot: a juiz component"
processes:
  - name: my_robot_add
    description: "Returns a + b."
    arguments:
      - { name: a, type: long, default: 0, description: "the first value" }
      - { name: b, type: long, default: 0, description: "the second value" }
    returns: long
containers:
  - name: my_robot
    description: "Holds an integer value."
    arguments:
      - { name: initial_value, type: long, default: 0, description: "the initial value" }
    state:
      - { name: value, type: long, init: initial_value }
    processes:
      - name: my_robot_increment
        description: "Adds step to the value and returns it."
        arguments:
          - { name: step, type: long, default: 1, description: "the value to add" }
        returns: long
      - name: my_robot_get
        description: "Returns the value."
        returns: long
        readonly: true
```

| キー | 意味 |
| --- | --- |
| `component` | Component の `name`(雛形の名前)、`description`、`language`(任意。`create -d` の `-b` を省いたときの言語) |
| `idl` | 任意。record・enum の型を書いた .jidl の場所(この文書からの相対パス)。`juiz_std/geometry.jidl` などの組み込みの型は名前だけで読めます |
| `processes` | Process の型。`name`・`description`・`arguments`・`returns`(省くと戻り値なし) |
| `containers` | Container の型。`arguments` は Container を作るときの引数(`app/app.conf` の `containers` の値)、`state` は Container が持つ値、`processes` はその Container の ContainerProcess |
| `arguments[]` | `name`・`type`・`default`(任意)・`description`(任意) |
| `state[]` | `name`・`type`・`init`(任意。初期値にする Container の引数の名前。省くと型の 0 値) |
| `readonly` | ContainerProcess だけ。`true` なら Container の状態を変えない ContainerProcess になります |

型は [データ型](../datatype/) の JIDL と同じ書き方です(`boolean`・`int`・`long`・`float`・`double`・`string`・`array<double>`・`image`・`T?`・`juiz_std.geometry.Pose2D` など)。record・enum を自分で定義するときは .jidl に書いて `idl:` で読みます。
1 行目のコメントは JSON Schema の場所なので、VS Code の YAML 拡張などでは、書いている途中から補完と形の検査が効きます。

### 検査する(juiz pkg design check)

```sh
juiz pkg design check juizdesign.yaml -b rust
# => ok: juizdesign.yaml (component my_robot: 1 process, 1 container, 2 container processes)
```

形・名前(重なり、言語のキーワード)・型(`idl:` の .jidl で解けるか)・既定値を確かめ、誤りはすべて場所付きで表示します。

```text
bad.yaml:12:24: error: containers[0].arguments[0].type: unknown type 'dobule' (it is not in the .jidl files in idl:)
error: bad.yaml is not a valid design document (1 error)
```

`-b` を省くと `component.language` の言語の規則で確かめます。どちらも無いときは、言語によらない検査だけをして警告を出します。`juiz pkg design`・`create -d` も、書く前に同じ検査をします。

### 設計文書から雛形を作る(create -d)

```sh
juiz pkg design my_robot              # juizdesign.yaml だけを書く
# juizdesign.yaml を書き直す
juiz pkg create -d juizdesign.yaml -b python
```

- 雛形の名前は `component.name` です(`<名前>`・`-t`・`--idl` とは一緒に使えません)。言語は `-b`、無ければ `component.language` です。
- 作り先は `-o`、省けば `./<component.name>` です。`-o .` のように、文書のあるディレクトリにそのまま雛形を作ることもできます(文書と `idl:` の .jidl だけがあるディレクトリなら作れます)。
- 雛形の直下に文書を `juizdesign.yaml` として写し、`idl:` の .jidl も同じ相対パスで写します。
- 関数の本体は書かれていません。Rust は `todo!()`、Python は `raise NotImplementedError`、C++ は `throw std::runtime_error`、Haskell は `error`、Zig は `return error.NotImplemented` が入っているので、書き換えてください。型・引数の既定値と説明・Container の状態の型と初期値・`readonly` は文書のとおりに書かれます。

`-t` で作る雛形も、中では組み込みの設計文書を通して作っています。`-t` と同じ文書を `create -d` に渡すと、型は同じで本体だけが空の雛形になります。
`--idl` で作るときは、.jidl の宣言から設計文書を作り、それを通して雛形を作ります(雛形の `juizdesign.yaml` の `idl:` に .jidl が書かれます)。`juiz pkg design <名前> --idl arm.jidl` で、.jidl から文書だけを書くこともできます。

### 型を足したとき

`juiz pkg add process|container` は、ソースと `app/app.conf` に加えて `juizdesign.yaml` にも、足した型を書き足します。0.3.4 までに作った雛形のように文書が無いときは、文書を直さずに警告だけ出します。

雛形を作った後で設計文書を書き換えても、雛形のソースは直りません。作り直すか、ソースを手で合わせてください。

### ビルドしたプラグインと突き合わせる

ビルドしたプラグインを開いて、中の型(manifest)が設計文書のとおりかを確かめられます。設計文書の無いプラグインから、文書を起こすこともできます。

```sh
juiz pkg design check juizdesign.yaml --plugin app/plugins/<ターゲット>/libmy_robot.so
juiz pkg design --from-plugin app/plugins/<ターゲット>/libmy_robot.so -b rust -o juizdesign.yaml
```

- `--plugin`: 型名・引数の名前と型と既定値・戻り値の型・`readonly` が違えばエラーにします。説明の違いは警告です。
- `--from-plugin`: プラグインの型から文書を書きます。Container の状態はプラグインに無いので書かれません(表示に従って `state:` を足してください)。record・enum は文書の隣の `idl/<名前>.jidl` に書かれます。
- プラグインの言語は `-b`、無ければ `component.language` です。`.py` なら Python と分かりますが、`.so`・`.dylib`・`.dll` では `-b` が要ります。
- プラグインを開くので、`juiz pkg` で打ってください(単体の `juiz-pkg` では使えません)。
- C++ のプラグインでは、Container の引数が manifest に載らないため比べられず、また `create -d` の雛形の `long`・`double` の引数や戻り値は型が manifest に載らないので、「比べなかった」という警告が出ます(エラーにはなりません)。

文書の細かい決まりは、juiz のリポジトリの [docs/spec/design.md](https://github.com/OpenJUIZ/juiz/blob/main/docs/spec/design.md) にあります。

## 配布する

`scripts/pack.sh`(Windows は `scripts\pack.ps1`)で release ビルドをして、`dist/<名前>-0.1.0.juizapp` を作ります。受け取った人は `juiz run` だけで動かせます。

```sh
scripts/pack.sh
juiz run dist/my_robot-0.1.0.juizapp
```

- 既にビルドしてあるものをそのまま入れるときは `scripts/pack.sh --no-build` です。
- 複数の OS のプラグインを 1 つの .juizapp に入れるときは、それぞれの OS で `scripts/dev.sh --release` して `app/plugins/<ターゲット>/` を 1 か所に集めてから `scripts/pack.sh --no-build` します。ターゲット名は `juiz pkg target` で表示できます。
- `--license mit-apache` で作ったときは、LICENSE-MIT・LICENSE-APACHE も .juizapp に入ります。
- パッケージの版は `0.1.0` から始まります。版を上げるときは、`app/juizapp.yaml` とビルドのファイル(Cargo.toml・pyproject.toml・CMakeLists.txt・.cabal・build.zig.zon)の両方を直してください。

.juizapp の中身や `juiz run` の動きは [アプリの配布(.juizapp)](../app-package/) を見てください。

## 版について

雛形には、`juiz pkg` を動かした juiz の版が書かれます。

| ファイル | 書き方 |
| --- | --- |
| Cargo.toml | `juiz_sdk = "=0.3.5"` |
| pyproject.toml | `pyjuiz==0.3.5` |
| CMakeLists.txt | `JUIZ_VERSION "0.3.5"`(`find_package(... EXACT)`) |
| cabal.project | hsjuiz・libjuiz_sdk のパスに版が入る |
| build.zig.zon | zigjuiz のアーカイブの URL に版が入る(`scripts/dev.sh` が初回に書く) |
| app/juizapp.yaml | `juiz: ">=0.3.5"`(C++・Haskell・Zig は `"=0.3.5"`) |

C++・Haskell・Zig の .juizapp は libjuiz_sdk を同梱するので、動かす juiz と版が一致しないと読み込めません。そのため `juiz: "=<版>"` にしてあり、違う版の juiz で `juiz run` すると、最初に版の違いを示して止まります。
juiz を上げたときは、雛形を作り直すか、上の表の版を手で直してください。

## juiz-pkg

同じものが単体のコマンド `juiz-pkg` としても入れられます(`cargo install juiz_pkg`)。引数と動きは `juiz pkg` と同じですが、雛形に書かれるのは juiz_pkg の版です。juiz と版がずれないよう、ふだんは `juiz pkg` を使ってください。
