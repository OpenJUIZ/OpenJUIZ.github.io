`juiz` コマンドの入れ方は 2 通りあります。使う言語で選んでください。

| 使う言語 | 入れ方 | Rust のツールチェーン |
| --- | --- | --- |
| Python・C++・Haskell | `pip install juiz-cli` | 不要 |
| Rust(Python・C++・Haskell も併用可) | `cargo install juiz_app` | 必要 |

C++ と Haskell の機能要素は、どちらの入れ方の `juiz` でも動きます(下の「[C++ と Haskell の共通: libjuiz_sdk](#c-と-haskell-の共通-libjuiz_sdk)」で、`juiz` と同じ版の libjuiz_sdk を用意します)。

## juiz コマンドを入れる

入れ方を選んでください。このページの下のほうにある Python の説明も、ここで選んだ入れ方に合わせて切り替わります。

<Tabs syncKey="install">
<TabItem label="pip で入れる">

PyPI の [juiz-cli](https://pypi.org/project/juiz-cli/) を入れると、`juiz` コマンドと、Process を書くための [pyjuiz](https://pypi.org/project/pyjuiz/)(`import juiz`)の両方が入ります。Rust のツールチェーンは要りません。

必要なもの:

- Python 3.10 以降
- Linux(x86_64・aarch64)、macOS(Apple シリコン・Intel)、Windows(x86_64)のいずれか

```sh
python3 -m venv .venv
source .venv/bin/activate        # Windows では .venv\Scripts\activate
pip install juiz-cli
juiz --help
```

`juiz` コマンドは venv の中に入ります。以降は、この venv を有効にしたターミナルで `juiz` を実行してください。
pyjuiz も一緒に入っているので、Python の Process を書くために追加で入れるものはありません。

<Aside type="caution">
pip で入れた `juiz` は、juiz の CI でビルドしたものです。手元でビルドした Rust のプラグイン(Rust で書いた Process など)は、コンパイラの版がそろわないため読み込めません。
Rust でも書く場合は、「cargo で入れる」の手順を使ってください。C++ と Haskell のプラグインは読み込めます。
</Aside>

</TabItem>
<TabItem label="cargo で入れる">

必要なもの:

- Linux または macOS
- Rust 1.81 以降([rustup](https://rustup.rs/) でインストール)
- C++ で機能要素を書く場合: CMake と C++17 対応のコンパイラ
- Python で機能要素も書く場合: Python 3 と開発用ヘッダー(Ubuntu なら `sudo apt install python3-dev python3-venv`)

crates.io で公開されている `juiz_app` をインストールします。

```sh
cargo install juiz_app --version 0.0.26 --locked
```

`juiz` コマンドが `~/.cargo/bin` に入ります。

**Python の Process も使う場合**

この `juiz` で Python の Process も動かすときは、PyPI の [pyjuiz](https://pypi.org/project/pyjuiz/) **だけ** を、`juiz` と同じ版で追加します。
`juiz` コマンドはビルド時に見つけた Python を組み込むので、同じ Python で venv を作ってください。

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install pyjuiz==0.0.26
```

<Aside type="caution">
cargo で入れた場合は、`juiz-cli` を入れないでください。`juiz` コマンドが 2 つになり、どちらが動くかが PATH の順番で決まってしまいます。
</Aside>

</TabItem>
</Tabs>

## 言語ごとのパッケージ

### Rust

機能要素は [juiz_sdk](https://crates.io/crates/juiz_sdk) クレートで書きます。`Cargo.toml` で共有ライブラリとしてビルドする設定にします。
juiz_sdk の版は、`cargo install juiz_app` で入れた `juiz` と合わせてください。版が食い違うプラグインは、読み込むときにエラーで止まります。

```toml
[lib]
crate-type = ["cdylib"]

[dependencies]
juiz_sdk = "0.0.26"
```

`Cargo.toml` の書き方は、[チュートリアル第 1 章(Rust)](/ja/tutorial/first-process/rust/) で 1 行ずつ説明しています。

### Python

[pyjuiz](https://pypi.org/project/pyjuiz/) のデコレータ(`from juiz import juiz_process` など)で書きます。

<Tabs syncKey="install">
<TabItem label="pip で入れる">

pyjuiz は `juiz-cli` と一緒に入っています。追加で入れるものはありません。

</TabItem>
<TabItem label="cargo で入れる">

上の「Python の Process も使う場合」のとおり、`juiz` と同じ版の pyjuiz だけを入れます。

```sh
pip install pyjuiz==0.0.26
```

</TabItem>
</Tabs>

### C++ と Haskell の共通: libjuiz_sdk

C++ と Haskell の機能要素は、libjuiz_sdk(値を受け渡す C の関数の共有ライブラリ)にリンクします。
libjuiz_sdk とヘッダは、OS・CPU ごとのアーカイブにして [GitHub Releases](https://github.com/OpenJUIZ/juiz/releases) に置いています(0.0.26 から)。
`juiz` と **同じ版** を使ってください。版が違う libjuiz_sdk でビルドしたプラグインは、juiz が読み込むときにエラーにします。

いちばん手軽なのは、OS と CPU を自動で見分けて取得する `install-juiz-sdk.sh` を使う方法です。`~/.juiz/sdk/<版>` に展開されます。

```sh
juiz --version      # 例: juiz 0.0.26
curl -fsSL https://raw.githubusercontent.com/OpenJUIZ/juiz/main/scripts/install-juiz-sdk.sh | sh -s -- 0.0.26
```

手でダウンロードする場合は、OS を選んで次のアーカイブを取得し、同じ場所に展開します。

<Tabs syncKey="os">
<TabItem label="Linux (x86_64)">

ダウンロード: [juiz_sdk-0.0.26-x86_64-unknown-linux-gnu.tar.gz](https://github.com/OpenJUIZ/juiz/releases/download/v0.0.26/juiz_sdk-0.0.26-x86_64-unknown-linux-gnu.tar.gz)

```sh
mkdir -p ~/.juiz/sdk
tar xzf juiz_sdk-0.0.26-x86_64-unknown-linux-gnu.tar.gz
mv juiz_sdk-0.0.26-x86_64-unknown-linux-gnu ~/.juiz/sdk/0.0.26
# => ~/.juiz/sdk/0.0.26/lib/libjuiz_sdk.so
```

</TabItem>
<TabItem label="Linux (aarch64)">

ダウンロード: [juiz_sdk-0.0.26-aarch64-unknown-linux-gnu.tar.gz](https://github.com/OpenJUIZ/juiz/releases/download/v0.0.26/juiz_sdk-0.0.26-aarch64-unknown-linux-gnu.tar.gz)

<TabItem label="Windows">

Windows 向けのアーカイブは、まだ配布していません。
juiz のソースを `juiz` と同じ版のタグで取得し、`cargo build --release -p juiz_sdk` でできる `target/release` の juiz_sdk を使ってください(ヘッダはソースの `bindings/cjuiz/include` と `bindings/cppjuiz/include`)。

</TabItem>
</Tabs>

展開したディレクトリには、次のものが入っています。

| 場所 | 中身 |
| --- | --- |
| `lib/` | libjuiz_sdk(Linux は `.so`、macOS は `.dylib`)と pkg-config 用の `pkgconfig/juiz_sdk.pc` |
| `cjuiz/include/` | C のヘッダ |
| `cppjuiz/include/` | C++ のヘッダ(`juiz/juiz.h`) |

0.0.25 以前の版では、Windows と同じく juiz のソースから libjuiz_sdk をビルドしてください。

### C++

インクルードパスに `~/.juiz/sdk/0.0.26/cjuiz/include` と `~/.juiz/sdk/0.0.26/cppjuiz/include` を足し、`~/.juiz/sdk/0.0.26/lib` の libjuiz_sdk にリンクします。
CMake の書き方は、[チュートリアル第 1 章(C++)](/ja/tutorial/first-process/cpp/) で 1 行ずつ説明しています。
サンプル集 [juiz_examples_cpp](https://github.com/OpenJUIZ/juiz_examples_cpp) の [cmake/Juiz.cmake](https://github.com/OpenJUIZ/juiz_examples_cpp/blob/main/cmake/Juiz.cmake) のように、libjuiz_sdk の取得まで CMake に任せることもできます。

### Haskell

[hsjuiz](https://github.com/OpenJUIZ/juiz/tree/main/bindings/hsjuiz) で書きます。GHC 9.4.7 以降と cabal が必要です(Linux・macOS)。
hsjuiz は Hackage への公開を待っているので、いまは juiz のソースを `juiz` と同じ版のタグで取得し、その `bindings/hsjuiz` から使います。自分のパッケージの `cabal.project` に、hsjuiz のソースと libjuiz_sdk の場所を書きます。

```sh
git clone --depth 1 --branch v0.0.26 https://github.com/OpenJUIZ/juiz.git ~/juiz-0.0.26
```

<Tabs syncKey="os">
<TabItem label="Linux (x86_64)">

```txt title="cabal.project"
package hsjuiz
  extra-lib-dirs: /home/me/.juiz/sdk/0.0.26/lib
  ghc-options: -optl-Wl,-rpath,/home/me/.juiz/sdk/0.0.26/lib
```

`/home/me`・`/Users/me` は自分のホームディレクトリに読み替えてください(`cabal.project` では `~` を使えません)。
rpath は、Template Haskell を動かすときに GHC が hsjuiz と一緒に libjuiz_sdk を読み込むために要ります。
サンプル集 [juiz_examples_haskell](https://github.com/OpenJUIZ/juiz_examples_haskell) の `build.sh` が、libjuiz_sdk と hsjuiz の取得からサンプルのビルドまでを自動で行うので、ひな形にも使えます。

書き方は [hsjuiz の README](https://github.com/OpenJUIZ/juiz/tree/main/bindings/hsjuiz) を見てください。

<Aside type="note">
hsjuiz は Hackage への公開を待っています。公開したら、`cabal.project` に hsjuiz のソースを書かずに Hackage から入れられるようになります。
</Aside>

## ソースからビルドする

開発版を使う場合はリポジトリをクローンしてビルドします。

```sh
git clone https://github.com/OpenJUIZ/juiz.git
cd juiz
cargo build
cargo install --path juiz_app
```
