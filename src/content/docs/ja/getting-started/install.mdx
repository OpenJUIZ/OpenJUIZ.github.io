`juiz` コマンドの入れ方は 2 通りあります。使う言語で選んでください。

| 使う言語 | 入れ方 | Rust のツールチェーン |
| --- | --- | --- |
| Python・C++・Haskell | `pip install juiz-cli` | 不要 |
| Rust(Python・C++・Haskell も併用可) | `cargo install juiz_app` | 必要 |

C++ と Haskell の機能要素は、どちらの入れ方の `juiz` でも動きます(「[言語ごとのパッケージ](/ja/getting-started/packages/#c-と-haskell-の共通-libjuiz_sdk)」で、`juiz` と同じ版の libjuiz_sdk を用意します)。

## juiz コマンドを入れる

入れ方を選んでください。[言語ごとのパッケージ](/ja/getting-started/packages/) の Python の説明も、ここで選んだ入れ方に合わせて切り替わります。

<Tabs syncKey="install">
<TabItem label="pip で入れる">

PyPI の [juiz-cli](https://pypi.org/project/juiz-cli/) を入れると、`juiz` コマンドと、Process を書くための [pyjuiz](https://pypi.org/project/pyjuiz/)(`import juiz`)の両方が入ります。Rust のツールチェーンは要りません。

必要なもの:

- Python 3.10 以降
- Linux(x86_64・aarch64)、macOS(Apple シリコン・Intel)、Windows(x86_64)のいずれか

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install juiz-cli
juiz --help
```

</TabItem>
<TabItem label="macOS">

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install juiz-cli
juiz --help
```

</TabItem>
<TabItem label="Windows">

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install juiz-cli
juiz --help
```

</TabItem>
</Tabs>

`juiz` コマンドは venv の中に入ります。以降は、この venv を有効にしたターミナルで `juiz` を実行してください。
pyjuiz も一緒に入っているので、Python の Process を書くために追加で入れるものはありません。

<Aside type="caution">
pip で入れた `juiz` は、juiz の CI でビルドしたものです。手元でビルドした Rust のプラグイン(Rust で書いた Process など)は、コンパイラの版がそろわないため読み込めません。
Rust でも書く場合は、「cargo で入れる」の手順を使ってください。C++ と Haskell のプラグインは読み込めます。
</Aside>

</TabItem>
<TabItem label="cargo で入れる">

必要なもの:

- Linux、macOS、Windows(x86_64)のいずれか
- Rust 1.81 以降([rustup](https://rustup.rs/) でインストール)
- Windows の場合: Visual Studio 2022 か Build Tools for Visual Studio 2022 の「C++ によるデスクトップ開発」(Rust の MSVC ツールチェーンが使うリンカーです。2019 でも動作を確認しています)
- C++ で機能要素を書く場合: CMake と C++17 対応のコンパイラ
- Python で機能要素も書く場合: Python 3 と開発用ヘッダー(Ubuntu なら `sudo apt install python3-dev python3-venv`。Windows は python.org のインストーラーで入れた Python なら追加で入れるものはありません)

crates.io で公開されている `juiz_app` をインストールします。Windows の PowerShell でも、同じコマンドで入れられます。

```sh
cargo install juiz_app --version 0.0.27 --locked
```

`juiz` コマンドが `~/.cargo/bin`(Windows では `%USERPROFILE%\.cargo\bin`)に入ります。

**Python の Process も使う場合**

この `juiz` で Python の Process も動かすときは、PyPI の [pyjuiz](https://pypi.org/project/pyjuiz/) **だけ** を、`juiz` と同じ版で追加します。
`juiz` コマンドはビルド時に見つけた Python を組み込むので、同じ Python で venv を作ってください。

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install pyjuiz==0.0.27
```

</TabItem>
<TabItem label="macOS">

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install pyjuiz==0.0.27
```

</TabItem>
<TabItem label="Windows">

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install pyjuiz==0.0.27
$env:PYTHONPATH = "$PWD\.venv\Lib\site-packages"
```

最後の行は、下の注意にある問題を避けるためのものです。

</TabItem>
</Tabs>

<Aside type="caution" title="Windows で cargo の juiz と Python を使うとき">
Windows では、cargo で入れた `juiz` が、有効にした venv のパッケージ(pyjuiz など)を読み込めません([juiz#296](https://github.com/OpenJUIZ/juiz/issues/296))。Python の Process を読み込むところで `ModuleNotFoundError: No module named 'juiz'` になります。
`juiz` を起動するターミナルで、venv の `Lib\site-packages` を環境変数 `PYTHONPATH` に入れてください。`$PWD` は今いるディレクトリなので、`.venv` を作ったディレクトリで実行します。

```powershell
$env:PYTHONPATH = "$PWD\.venv\Lib\site-packages"
```

この設定は、そのターミナルを閉じると消えます。juiz 0.0.28 以降では不要になる予定です。
</Aside>

<Aside type="caution">
cargo で入れた場合は、`juiz-cli` を入れないでください。`juiz` コマンドが 2 つになり、どちらが動くかが PATH の順番で決まってしまいます。
</Aside>

</TabItem>
</Tabs>

## 次に読むもの

`juiz` コマンドを入れたら、機能要素を書く言語のパッケージを [言語ごとのパッケージ](/ja/getting-started/packages/) で用意してください(Python を pip で入れた場合は、追加で入れるものはありません)。

## ソースからビルドする

開発版を使う場合はリポジトリをクローンしてビルドします。

```sh
git clone https://github.com/OpenJUIZ/juiz.git
cd juiz
cargo build
cargo install --path juiz_app
```
