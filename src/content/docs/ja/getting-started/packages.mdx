[インストール](/ja/getting-started/install/) で `juiz` コマンドを入れたら、機能要素を書く言語のパッケージを用意します。使う言語の節だけ読めば十分です。

## Rust

機能要素は [juiz_sdk](https://crates.io/crates/juiz_sdk) クレートで書きます。`Cargo.toml` で共有ライブラリとしてビルドする設定にします。
juiz_sdk の版は、`cargo install juiz_app` で入れた `juiz` と合わせてください。版が食い違うプラグインは、読み込むときにエラーで止まります。

```toml
[lib]
crate-type = ["cdylib"]

[dependencies]
juiz_sdk = "0.0.26"
```

`Cargo.toml` の書き方は、[チュートリアル第 1 章(Rust)](/ja/tutorial/first-process/rust/) で 1 行ずつ説明しています。

## C++ と Haskell の共通: libjuiz_sdk

C++ と Haskell の機能要素は、libjuiz_sdk(値を受け渡す C の関数の共有ライブラリ)にリンクします。
libjuiz_sdk とヘッダは、OS・CPU ごとのアーカイブにして [GitHub Releases](https://github.com/OpenJUIZ/juiz/releases) に置いています(0.0.26 から)。
`juiz` と **同じ版** を使ってください。版が違う libjuiz_sdk でビルドしたプラグインは、juiz が読み込むときにエラーにします。

いちばん手軽なのは、OS と CPU を自動で見分けて取得する `install-juiz-sdk.sh`(Windows は `install-juiz-sdk.ps1`)を使う方法です。`~/.juiz/sdk/<版>`(Windows は `%USERPROFILE%\.juiz\sdk\<版>`)に展開されます。

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
juiz --version      # 例: juiz 0.0.26
curl -fsSL https://raw.githubusercontent.com/OpenJUIZ/juiz/main/scripts/install-juiz-sdk.sh | sh -s -- 0.0.26
```

</TabItem>
<TabItem label="macOS">

```sh
juiz --version      # 例: juiz 0.0.26
curl -fsSL https://raw.githubusercontent.com/OpenJUIZ/juiz/main/scripts/install-juiz-sdk.sh | sh -s -- 0.0.26
```

</TabItem>
<TabItem label="Windows">

PowerShell で実行します。Windows 向けは 0.0.27 からです。

```powershell
juiz --version      # 例: juiz 0.0.27
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/OpenJUIZ/juiz/main/scripts/install-juiz-sdk.ps1))) 0.0.27
```

</TabItem>
</Tabs>

手でダウンロードする場合は、OS を選んで次のアーカイブを取得し、同じ場所に展開します。

ダウンロード: [juiz_sdk-0.0.27-x86_64-pc-windows-msvc.zip](https://github.com/OpenJUIZ/juiz/releases/download/v0.0.27/juiz_sdk-0.0.27-x86_64-pc-windows-msvc.zip)

```powershell

Expand-Archive juiz_sdk-0.0.27-x86_64-pc-windows-msvc.zip -DestinationPath .
Move-Item juiz_sdk-0.0.27-x86_64-pc-windows-msvc $env:USERPROFILE\.juiz\sdk\0.0.27
# => %USERPROFILE%\.juiz\sdk\0.0.27\bin\juiz_sdk.dll
```

展開したディレクトリには、次のものが入っています。

| 場所 | 中身 |
| --- | --- |
| `lib/` | libjuiz_sdk(Linux は `.so`、macOS は `.dylib`)と pkg-config 用の `pkgconfig/juiz_sdk.pc`。Windows はリンクに使うインポートライブラリ `juiz_sdk.dll.lib` |
| `bin/` | Windows だけ。libjuiz_sdk の DLL `juiz_sdk.dll` |
| `lib/cmake/juiz_sdk/` | CMake の `find_package(juiz_sdk)` 用の設定(0.0.27 から) |
| `cjuiz/include/` | C のヘッダ |
| `cppjuiz/include/` | C++ のヘッダ(`juiz/juiz.h`) |

0.0.25 以前の版では、juiz のソースを `juiz` と同じ版のタグで取得し、`cargo build --release -p juiz_sdk` で libjuiz_sdk をビルドしてください。

## C++

CMake では、0.0.27 から `find_package` で libjuiz_sdk を使えます。`CMAKE_PREFIX_PATH`(または `find_package` の `PATHS`)に展開したディレクトリを指定します。

```cmake
find_package(juiz_sdk 0.0.27 EXACT CONFIG REQUIRED)
add_library(my_process SHARED my_process.cpp)
target_link_libraries(my_process PRIVATE juiz_sdk::juiz_sdk)
juiz_sdk_copy_runtime(my_process)   # Windows では juiz_sdk.dll をプラグインの隣に写す
```

`juiz_sdk::juiz_sdk` にはヘッダの場所と C++17 の指定も入っています。Windows では、juiz はプラグインの DLL が使う `juiz_sdk.dll` をプラグインと同じ場所(と `PATH`)から探すので、`juiz_sdk_copy_runtime` で隣に写しておきます。
CMake の書き方は、[チュートリアル第 1 章(C++)](/ja/tutorial/first-process/cpp/) で 1 行ずつ説明しています。

CMake を使わない場合は、インクルードパスに `cjuiz/include` と `cppjuiz/include` を足し、`lib` の libjuiz_sdk(Windows は `lib/juiz_sdk.dll.lib`)にリンクします。
サンプル集 [juiz_examples_cpp](https://github.com/OpenJUIZ/juiz_examples_cpp) の [cmake/Juiz.cmake](https://github.com/OpenJUIZ/juiz_examples_cpp/blob/main/cmake/Juiz.cmake) のように、libjuiz_sdk の取得まで CMake に任せることもできます。

## Haskell

[hsjuiz](https://github.com/OpenJUIZ/juiz/tree/main/bindings/hsjuiz) で書きます。GHC 9.4.7 以降と cabal が必要です(Linux・macOS)。
hsjuiz は Hackage への公開を待っているので、いまは juiz のソースを `juiz` と同じ版のタグで取得し、その `bindings/hsjuiz` から使います。自分のパッケージの `cabal.project` に、hsjuiz のソースと libjuiz_sdk の場所を書きます。

```sh
git clone --depth 1 --branch v0.0.26 https://github.com/OpenJUIZ/juiz.git ~/juiz-0.0.26
```

<Tabs syncKey="os">
<TabItem label="Linux (x86_64)">

package hsjuiz

  ghc-options: -optl-Wl,-rpath,/home/me/.juiz/sdk/0.0.26/lib

`/home/me`・`/Users/me` は自分のホームディレクトリに読み替えてください(`cabal.project` では `~` を使えません)。
rpath は、Template Haskell を動かすときに GHC が hsjuiz と一緒に libjuiz_sdk を読み込むために要ります。
サンプル集 [juiz_examples_haskell](https://github.com/OpenJUIZ/juiz_examples_haskell) の `build.sh` が、libjuiz_sdk と hsjuiz の取得からサンプルのビルドまでを自動で行うので、ひな形にも使えます。

書き方は [hsjuiz の README](https://github.com/OpenJUIZ/juiz/tree/main/bindings/hsjuiz) を見てください。

<Aside type="note">
hsjuiz は Hackage への公開を待っています。公開したら、`cabal.project` に hsjuiz のソースを書かずに Hackage から入れられるようになります。
</Aside>
