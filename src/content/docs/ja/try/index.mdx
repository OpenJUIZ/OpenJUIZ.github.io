ここでは、juiz で作られたアプリを組み合わせて、シミュレータの中の移動ロボットを動かしてみます。
コードを書いたりビルドしたりはしません。配布されている `.juizapp` を取ってきて、`juiz run` で起動するだけです。

1. キーボードやゲームパッドでロボットを走らせ、
2. LiDAR とオドメトリから **SLAM**(Simultaneous Localization and Mapping、自己位置の推定と地図づくりを同時に行う技術)で部屋の地図を作り、
3. 最後に、その地図の上でロボットがゴールまで自分で走る**自律移動**(ナビゲーション)をさせます。

[チュートリアル](/ja/tutorial/) が「juiz の機能を 1 つずつ学ぶ」ためのものなのに対して、ここは「できあがったものを動かして、全体がどうつながっているかを見る」ためのものです。チュートリアルを終えていなくても始められます。

<Aside type="tip" title="この一巡りでわかること">
- 別々に配布された juiz アプリが、トピックと ID でつながって 1 つのロボットシステムになる様子
- オドメトリ(車輪の回転から求めた位置)にはずれが積み重なり、SLAM や自己位置推定がそれを地図と照らし合わせて直す様子
- 座標系(Transformations)が別々のアプリをまたいで 1 本の木になる様子
- トピックで流し続けるもの(センサーの値、速度の指令)と、HTTP で呼ぶもの(ゴール、経路、地図)の使い分け
</Aside>

## 使うアプリ

どれも OpenJUIZ で公開しています。navigation_manager 以外は `.juizapp` です。

| アプリ | 役割 | 画面 |
| --- | --- | --- |
| mobile_sim | 平面を走る移動ロボットのシミュレータ。LiDAR のスキャンとオドメトリを出す | http://localhost:8000/ |
| teleop_twist | ブラウザでキーボードかゲームパッドの入力を読み、速度の指令を出す | http://localhost:8002/ |
| mapper_gmapping | GMapping で、スキャンとオドメトリから地図と自己位置を推定する | http://localhost:8001/ |
| localization_amcl | AMCL(粒子フィルタ)で、地図の上のロボットの位置を推定する | http://localhost:8002/ |
| planner_dijkstra | ゴールまでの道筋(大域経路)をダイクストラ法で求める | http://localhost:8003/ |
| planner_dwa | 大域経路に沿いながら障害物をよける速度の指令を DWA で求める | http://localhost:8004/ |
| navigation_hub | 自律移動のアプリを 1 本の木にまとめ、トピックを中継する | http://localhost:8006/ |
| navigation_manager | ゴールを受けて計画させ、追わせ、着いたかを判断する(Python、pip で入れる) | http://localhost:8005/ |

teleop_twist と localization_amcl はどちらも 8002 番を使うので、前半(1〜3)と後半(4〜6)で入れ替えます。

### SHA-256 を確かめる

7 つのファイルの SHA-256 は次のとおりです。この内容を、作業用のディレクトリに `SHA256SUMS` という名前で保存してください。

```text title="SHA256SUMS"
a6aebb0aa9b1e625c95669fcc3c880816629f721e11e342e7ee3b44425c9efa7  mobile_sim-0.3.5.juizapp
e58f32abaf0db9690d8b13cf42f43efdf6cc9b1831795a9d1704eadb136c88a5  teleop_twist-0.1.0.juizapp
64b13b909f13e25fc637302bd9f136c8b5a66d7e5a9578682f5514166f0082e8  mapper_gmapping-0.4.2.juizapp
f9ace568fe7d689f2d15e9ebdac59ceadd5565e9cdd5fba9cb6aa2e50f0bebbd  localization_amcl-0.1.3.juizapp
0e8dcf40996579c27bab59c545c336b0cc5935e9a4143c986bc862e93ed7d59d  planner_dijkstra-0.2.2.juizapp
f14a4d4a511ddae7520d0e361a34d1d9060b38bf87c08e7aaf3104584c4725fc  planner_dwa-0.1.2.juizapp
ae0c992f1ca0808e51df5dad3cd6df3396e8af4460b6debdc9f166ae86526327  navigation_hub-0.3.4.juizapp
```

そのうえで、次のコマンドで確かめます。

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
sha256sum -c SHA256SUMS
```

</TabItem>
<TabItem label="macOS">

```sh
shasum -a 256 -c SHA256SUMS
```

</TabItem>
<TabItem label="Windows">

```powershell
Get-Content SHA256SUMS | ForEach-Object {
    $hash, $file = $_ -split '\s+'
    if ((Get-FileHash $file -Algorithm SHA256).Hash -eq $hash) { "${file}: OK" } else { "${file}: FAILED" }
}
```

</TabItem>
</Tabs>

7 行とも `OK` と出れば大丈夫です。`FAILED` と出たファイルは、消してからダウンロードし直してください。

<Aside type="note" title="この値はどこから来ているか">
各 Release には、`SHA256SUMS` のようなチェックサムのファイルは置いていません。
上の値は、GitHub が Release ページで各ファイルの横に表示している SHA-256 と同じものです(表の「Release」のリンクから見られます)。
新しい版を取ってくるときは、その版の Release ページに出ている値と比べてください。

なお `juiz run` も、パッケージの中のファイルが `juizapp.yaml` に書かれた SHA-256 と合っているかを、展開するときに確かめます。ただしこれは「パッケージの中身がそろっているか」の確認で、パッケージそのものがすり替わっていないかは、ここでの確認で確かめます。
</Aside>

## ターミナル

ターミナルを最大 4 つ使います。どれも作業用のディレクトリで開いておいてください(pip で venv に入れた場合は、どのターミナルでも venv を有効にしておきます)。

| ターミナル | 1〜3(地図を作る) | 4〜6(自律移動) |
| --- | --- | --- |
| 1 | mobile_sim | 一式(`navigation-manager stack`) |
| 2 | teleop_twist | `juiz` コマンドなどで中を見る |
| 3 | mapper_gmapping | 使わない |
| 4 | `juiz` コマンドで中を見る | 使わない |
