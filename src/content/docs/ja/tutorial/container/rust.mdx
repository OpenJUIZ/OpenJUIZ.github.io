第 1 章の Process は、同じ引数を渡せばいつも同じ結果を返す冪等な関数でした。
しかし、ロボットや IoT の部品を作っていると、カウンタの値やモータの現在位置、カメラの接続のように「覚えておきたいもの」が必ず出てきます。
この章では、整数を 1 つ覚えておくカウンタを、第 1 章で作ったプロジェクト `my_juiz` に足していきます。

<Aside type="tip" title="この章で学ぶこと">
- 状態は **Container** に置き、Process には持たせないこと
- 状態に触れるのは、Container に結びついた **ContainerProcess** だけであること
- 1 つの Container に、役割の違う ContainerProcess をいくつも結びつけられること
- `juiz pkg add container` で、プロジェクトに Container と ContainerProcess を足す方法
</Aside>

## Container を足す

第 1 章のプロジェクト `my_juiz` で、次のコマンドを打ちます。`juiz` を起動したままなら、Ctrl+C で止めておいてください。

```sh
juiz pkg add container counter
```

```text
Added container counter to my_juiz (rust): counter, counter_increment, counter_get
Edited src/lib.rs, app/app.conf, juizdesign.yaml

Next steps:
  scripts/dev.sh                  # rebuild the plugin
  juiz -f app/app.conf -d         # restart juiz
  ...
```

`juiz pkg add container <名前>` は、次の 3 つの型を足します。

| 役割 | 型名 | 内容 |
| --- | --- | --- |
| Container | `counter` | カウンタの値を 1 つ持つ。作るときに初期値 `initial_value` を受け取る |
| ContainerProcess | `counter_increment` | Container の値に `step` を足して、足した後の値を返す |
| ContainerProcess | `counter_get` | Container の値をそのまま返す |

書き換わるのは `src/lib.rs` と `app/app.conf`、それに設計文書 `juizdesign.yaml` の 3 つだけで、新しいファイルは増えません。
足された型も、第 1 章の Process と同じ 1 つのライブラリ(Component)に入ります。`Cargo.toml` を直す必要もありません。

足されたところを順に読んでいきます。

## Container: 状態を入れておく

Container は、状態そのものです。値を入れておく入れ物と、それを作る関数だけが書かれています。

```rust title="src/lib.rs(足された部分)"
/// State of the container `counter`.
#[repr(Rust)]
pub struct Counter {
    pub value: i64,
}

#[juiz_component_container(
    typed = "all"
    description = "Holds an integer value."
    arguments = {
        default = { initial_value = 0 }
        description = {
            initial_value = "the initial value"
        }
    }
)]
fn counter(initial_value: i64) -> JuizResult<Box<Counter>> {
    Ok(Box::new(Counter {
        value: initial_value,
    }))
}
```

| 部分 | 意味 |
| --- | --- |
| `pub struct Counter` | 状態を入れておく構造体です。ここではカウンタの値 `value` を 1 つ持ちます |
| `#[juiz_component_container(...)]` | この関数を Container の作り方にします。関数名 `counter` が Container の**型名**になります |
| `initial_value: i64` | Container を作るときに受け取る値です。既定値は 0 で、設定ファイルから渡せます(第 3 章) |
| `JuizResult<Box<Counter>>` | 作った状態を `Box` に入れて返します |

Container には、値を変えたり読んだりする処理は書いていません。Container は「何を覚えておくか」だけを表します。

## ContainerProcess: 状態を変える・読む

状態を変えたり読んだりする処理は、ContainerProcess に書きます。
ContainerProcess は、**最初の引数に Container を受け取る** Process です。どの Container と組になるかは、Container の型名で指定します。

### counter_increment: 値を足す

```rust title="src/lib.rs(足された部分)"
#[juiz_component_container_process(
    container_type = "counter"
    typed = "all"
    description = "Adds step to the value and returns it."
    arguments = {
        default = { step = 1 }
        description = {
            step = "the value to add"
        }
    }
)]
fn counter_increment(container: &mut ContainerImpl<Counter>, step: i64) -> JuizResult<i64> {
    container.value += step;
    Ok(container.value)
}
```

| 部分 | 意味 |
| --- | --- |
| `#[juiz_component_container_process(...)]` | この関数を ContainerProcess にします。関数名 `counter_increment` が型名になります |
| `container_type = "counter"` | 結びつける Container の型名です |
| `typed = "all"`、`arguments = { default = { ... } description = { ... } }` | 第 1 章の Process と同じく、型を manifest に載せる指定と、引数 `step` の既定値・説明です |
| `container: &mut ContainerImpl<Counter>` | 最初の引数で Container を受け取ります。`container.value` のように中の値を読み書きできます |
| `step: i64` | 2 番目以降の引数は、第 1 章の Process と同じように呼び出すときに渡します |

### counter_get: 値を読む

```rust title="src/lib.rs(足された部分)"
/// Receiving the container as `&ContainerImpl` (not `&mut`) makes this ContainerProcess readonly.
#[juiz_component_container_process(
    container_type = "counter"
    typed = "all"
    description = "Returns the value."
)]
fn counter_get(container: &ContainerImpl<Counter>) -> JuizResult<i64> {
    Ok(container.value)
}
```

`counter_get` は Container 以外の引数を持たず、値を返すだけです。
Container を `&mut` ではなく `&ContainerImpl<Counter>` で受け取っているので、値を書き換えられません。こうした「読むだけ」の ContainerProcess を **readonly** と呼びます。
juiz は、同じ Container の readonly の ContainerProcess どうしを、並行に動かすことがあります。

こうして、状態(Container)と振る舞い(ContainerProcess)を別々に書きます。
状態を変えたり読んだりできるのは、その Container に結びついた ContainerProcess だけです。
「この値はどこで書き換わるのか」を知りたいときは、ContainerProcess を見ればよいことになります。

### 型の一覧

ファイルの末尾の `juiz_component_manifest!` にも、足した型が書き足されています。

```rust title="src/lib.rs" ins={3-5}
juiz_component_manifest!(
    component_name = "my_juiz"
    containers = {
        counter = [ counter_increment, counter_get ]
    }
    processes = [ my_juiz_add ]
);
```

`containers` には、Container の型名と、それに結びつく ContainerProcess の関数名を並べます。

## 設定ファイルに足されたもの

`app/app.conf` の末尾には、`containers` が足されています。

```yaml title="app/app.conf" ins={4-12}
"processes":
  - "type_name": "my_juiz_add"
    "name": "my_juiz_add0"
"containers":
  - "type_name": "counter"
    "name": "counter0"
    "initial_value": 0
    "processes":
      - "type_name": "counter_increment"
        "name": "counter_increment0"
      - "type_name": "counter_get"
        "name": "counter_get0"
```

- 型 `counter` から、Container のインスタンス `counter0` を 1 つ作る。`initial_value` に 0 を渡す
- `counter0` に結びつけて、`counter_increment` のインスタンス `counter_increment0` と、`counter_get` のインスタンス `counter_get0` を作る

「1 つの Container に、2 つの ContainerProcess がぶら下がっている」という形です。設定ファイルの書き方は、次の第 3 章で詳しく扱います。

## 外から呼び出す

`juiz` を起動したまま、別のターミナルを開きます。まず、動いている Container と ContainerProcess の一覧を見ます(表示される順番は実行ごとに変わることがあります)。

```sh
juiz container list
# => ["http://127.0.0.1:8000/container/counter0::counter"]
juiz container-process list
# => ["http://127.0.0.1:8000/container_process/counter_increment0::counter_increment:counter0", "http://127.0.0.1:8000/container_process/counter_get0::counter_get:counter0"]
```

ContainerProcess の ID は「インスタンス名`::`型名`:`Container のインスタンス名」の形をしていて、どの Container に結びついているかが ID からわかります。

`counter_get` で今の値を見てから、`counter_increment` を同じ引数で 2 回呼び出し、もう一度 `counter_get` で値を見てみましょう。

```sh
juiz container-process call "http://127.0.0.1:8000/container_process/counter_get0::counter_get:counter0" '{}' -p
# => CapsulePtr((value:Value(0), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/counter_increment0::counter_increment:counter0" '{"step": 5}' -p
# => CapsulePtr((value:Value(5), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/counter_increment0::counter_increment:counter0" '{"step": 5}' -p
# => CapsulePtr((value:Value(10), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/counter_get0::counter_get:counter0" '{}' -p
# => CapsulePtr((value:Value(10), option: []))
```

同じ `{"step": 5}` を渡しているのに、1 回目と 2 回目で結果が違います。
第 1 章の Process と違って、ContainerProcess の結果は引数だけでなく Container の状態にも左右されるからです。

そして、`counter_increment` が変えた値を、別の ContainerProcess である `counter_get` が読めています。2 つの ContainerProcess は、同じ Container を共有しています。

`'{}'` のように `step` を省くと、既定値の 1 が足されます。
管理画面(`http://localhost:8000/ui/`)からも、第 1 章と同じように ContainerProcess を呼び出せます。

## やってみよう

- `counter_increment` に負の数(`{"step": -3}` など)を渡して、値が減ることを確かめてみましょう。
- `juiz` を Ctrl+C で止めてから起動し直し、`counter_get` を呼び出してみましょう。値は最初に戻っています。状態は、動いている Container の中にだけあることがわかります。
- 値を 0 に戻す ContainerProcess `counter_reset` を、自分で書き足してみましょう。`counter_increment` をまねて関数を書き(`container.value = 0;` にして値を返す)、`juiz_component_manifest!` の `counter = [ ... ]` に `counter_reset` を足し、`app/app.conf` の `counter0` の `processes` に `counter_reset0` のインスタンスを足します。

## まとめ

- `juiz pkg add container <名前>` で、Container と、それを読み書きする ContainerProcess をプロジェクトに足せます。書き換わるのはソースと `app/app.conf`、`juizdesign.yaml` だけです。
- 状態は Container に置きます。Container には「何を覚えておくか」だけを書き、処理は書きません。
- 状態を読み書きするのは、Container に結びついた ContainerProcess だけです。ContainerProcess は最初の引数で Container を受け取ります。Rust では、`&ContainerImpl` で受け取ると readonly になります。
- 1 つの Container に、役割の違う ContainerProcess をいくつも結びつけられます。それらは同じ状態を共有します。
- ContainerProcess の結果は、引数だけでなく Container の状態にも左右されます。冪等な Process と、状態を扱う ContainerProcess を分けておくことで、状態がどこで変わるのかがはっきりします。
