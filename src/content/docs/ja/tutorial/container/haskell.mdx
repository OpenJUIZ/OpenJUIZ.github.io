import { Tabs, TabItem, Aside, FileTree } from '@astrojs/starlight/components';

第 1 章の Process は、同じ引数を渡せばいつも同じ結果を返す冪等な関数でした。
しかし、ロボットや IoT の部品を作っていると、カウンタの値やモータの現在位置、カメラの接続のように「覚えておきたいもの」が必ず出てきます。
この章では、整数を 1 つ覚えておくカウンタを、第 1 章で作ったプロジェクト `my_juiz_hs` に足していきます。
できあがるものは、サンプル集 [juiz_examples_haskell](https://github.com/OpenJUIZ/juiz_examples_haskell) の `container/` と同じです。

<Aside type="tip" title="この章で学ぶこと">
- 状態は **Container** に置き、Process には持たせないこと
- 状態に触れるのは、Container に結びついた **ContainerProcess** だけであること
- 1 つの Container に、役割の違う ContainerProcess をいくつも結びつけられること
- 状態の型を ContainerProcess と共有する `.cabal` の書き方
</Aside>

## プロジェクトの形

この章では、第 1 章のプロジェクトに `container/` を足して、次の形にします。

<FileTree>
- my_juiz_hs/
  - cabal.project 第 1 章のまま
  - my-juiz-hs.cabal foreign-library を 3 つ足す
  - build.sh 第 1 章のまま
  - example_container.conf 起動用の設定ファイル(新しく作る)
  - process/
    - IncrementProcess.hs 第 1 章で作った Process
  - container/
    - ExampleContainerState.hs 状態の型(3 つのライブラリで共有する)
    - ExampleContainer.hs Container(カウンタの値)
    - ExampleContainerIncrement.hs ContainerProcess(値を足す)
    - ExampleContainerGet.hs ContainerProcess(値を読む)
</FileTree>

ディレクトリを作ります。以降のコマンドは、すべて `my_juiz_hs` で実行します。

```sh
cd my_juiz_hs
mkdir container
```

## Container を書く

Container は、状態そのものです。値を入れておく入れ物と、それを作る関数だけを書きます。

まず、状態の型を別のモジュールに書きます。
Container と ContainerProcess は別々の共有ライブラリになるので、どちらからも同じモジュールの同じ型を使って、型をそろえます。

```haskell title="container/ExampleContainerState.hs"
-- | example_container_hs の状態の型。
-- Container と ContainerProcess の両方のライブラリに入れて、型をそろえる。
module ExampleContainerState
  ( ExampleContainer (..)
  ) where

import Data.IORef (IORef)
import Data.Int (Int64)

-- | 保持している値。ContainerProcess が書き換えるので IORef に入れる
newtype ExampleContainer = ExampleContainer (IORef Int64)
```

Haskell の値は書き換えられないので、書き換えたい値は `IORef` に入れておきます。

```haskell title="container/ExampleContainer.hs"
{-# LANGUAGE OverloadedStrings #-}
{-# LANGUAGE TemplateHaskell #-}
-- | 整数値を 1 つ保持する Container (example_container_hs)。
-- 初期値は設定ファイルの containers に書いた value (無ければ 0)。
module ExampleContainer () where

import Juiz

import ExampleContainerState

manifest :: ContainerManifest
manifest = containerManifest "example_container_hs"
  & description "Holds an integer value."
  & addIntArg "value" "initial value" 0

create :: Int64 -> IO ExampleContainer
create value = ExampleContainer <$> newIORef value

juizContainer 'create 'manifest
```

| 部分 | 意味 |
| --- | --- |
| `containerManifest "example_container_hs"` | Container の説明書です。文字列が Container の**型名**になります |
| `addIntArg "value" "initial value" 0` | Container を作る関数の引数です。設定ファイルの `containers` に `value` を書くと、その値を受け取ります(第 3 章)。書いていなければ既定値の 0 になります |
| `create :: Int64 -> IO ExampleContainer` | Container を作る関数です。結果が Container の状態になります |
| `juizContainer 'create 'manifest` | `juiz` から読み込めるように公開します |

Container には、値を変えたり読んだりする処理は書いていません。Container は「何を覚えておくか」だけを表します。

## ContainerProcess を書く

状態を変えたり読んだりする処理は、ContainerProcess に書きます。
ContainerProcess は、**最初の引数に Container の状態を受け取る** Process です。どの Container と組になるかは、Container の型名で指定します。

### increment: 値を足す

```haskell title="container/ExampleContainerIncrement.hs"
{-# LANGUAGE OverloadedStrings #-}
{-# LANGUAGE TemplateHaskell #-}
-- | example_container_hs の値に arg1 を足し、足した後の値を返す ContainerProcess
-- (example_container_hs_increment)。
module ExampleContainerIncrement () where

import Juiz

import ExampleContainerState

manifest :: ProcessManifest
manifest = containerProcessManifest "example_container_hs_increment" "example_container_hs"
  & description "Adds arg1 to the value of the container."
  & addIntArg "arg1" "value to be added" 1

-- | 最初の引数で Container の状態を受け取る
increment :: ExampleContainer -> Int64 -> IO Int64
increment (ExampleContainer ref) arg1 = atomicModifyIORef' ref (\v -> (v + arg1, v + arg1))

juizContainerProcess 'increment 'manifest
```

| 部分 | 意味 |
| --- | --- |
| `import ExampleContainerState` | Container と同じ状態の型を使います |
| `containerProcessManifest "example_container_hs_increment" "example_container_hs"` | ContainerProcess の説明書です。1 つ目が ContainerProcess の型名、2 つ目が結びつける Container の型名です |
| `ExampleContainer -> Int64 -> IO Int64` | 最初の引数で Container の状態を受け取ります。続けて `manifest` で宣言した引数を受け取ります |
| `atomicModifyIORef'` | `IORef` の値を書き換えて、書き換えた後の値を返します |
| `juizContainerProcess 'increment 'manifest` | 公開には `juizProcess` ではなく `juizContainerProcess` を使います |

### get: 値を読む

```haskell title="container/ExampleContainerGet.hs"
{-# LANGUAGE OverloadedStrings #-}
{-# LANGUAGE TemplateHaskell #-}
-- | example_container_hs の値を返す ContainerProcess (example_container_hs_get)。引数は無い。
module ExampleContainerGet () where

import Juiz

import ExampleContainerState

manifest :: ProcessManifest
manifest = containerProcessManifest "example_container_hs_get" "example_container_hs"
  & description "Returns the value of the container."

get :: ExampleContainer -> IO Int64
get (ExampleContainer ref) = readIORef ref

juizContainerProcess 'get 'manifest
```

`get` は Container 以外の引数を持たず、値を返すだけです。

こうして、状態(Container)と振る舞い(ContainerProcess)を別々に書きます。
状態を変えたり読んだりできるのは、その Container に結びついた ContainerProcess だけです。
「この値はどこで書き換わるのか」を知りたいときは、ContainerProcess を見ればよいことになります。

<Aside type="note">
juiz は、同じ Container の ContainerProcess を同時には呼びません。ここでは `atomicModifyIORef'` を使っていますが、`modifyIORef'` と `readIORef` を続けて書いてもかまいません。
</Aside>

## my-juiz-hs.cabal に足す

`my-juiz-hs.cabal` の最後に、次の内容を足します。第 1 章で作った `common plugin` を使うので、1 つの `foreign-library` は数行で済みます。

```txt title="my-juiz-hs.cabal(末尾に追加)"
-- 第 2 章: カウンタの Container と ContainerProcess
-- 状態の型 (ExampleContainerState) は 3 つのライブラリのどれにも入れる
foreign-library example_container_hs
    import:           plugin
    type:             native-shared
    hs-source-dirs:   container
    other-modules:    ExampleContainer
                      ExampleContainerState

foreign-library example_container_hs_increment
    import:           plugin
    type:             native-shared
    hs-source-dirs:   container
    other-modules:    ExampleContainerIncrement
                      ExampleContainerState

foreign-library example_container_hs_get
    import:           plugin
    type:             native-shared
    hs-source-dirs:   container
    other-modules:    ExampleContainerGet
                      ExampleContainerState
```

3 つのライブラリの `other-modules` に、どれも `ExampleContainerState` を入れています。
juiz は Container の状態の型と ContainerProcess が受け取る型を、モジュール名つきの型名(`ExampleContainerState.ExampleContainer`)で比べます。違う型の Container に結びつけると、呼び出しがエラーになります。

## 動かす

まずは第 1 章と同じように、ファイルを指定して `juiz` を起動します。
Container は `--container`、ContainerProcess は `--container_process` で読み込みます。

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
juiz --container ./build/plugins/libexample_container_hs.so \
     --container_process ./build/plugins/libexample_container_hs_increment.so -l haskell -1 -d
```

</TabItem>
<TabItem label="macOS">

```sh
juiz --container ./build/plugins/libexample_container_hs.dylib \
     --container_process ./build/plugins/libexample_container_hs_increment.dylib -l haskell -1 -d
```

</TabItem>
</Tabs>

`-1` を付けると、読み込んだ Container の型からインスタンスを 1 つ作り、そこに ContainerProcess のインスタンスを 1 つ結びつけます。
インスタンス名は第 1 章と同じく型名の後ろに `0` を付けた名前で、Container は `example_container_hs0`、ContainerProcess は `example_container_hs_increment0` になります。
Container は値 0(`value` の既定値)から始まります。

## 外から呼び出す

`juiz` を起動したまま、別のターミナルを開きます。まず、動いている ContainerProcess の一覧を見ます。

```sh
juiz container-process list
# => ["http://127.0.0.1:8000/container_process/example_container_hs_increment0::example_container_hs_increment:example_container_hs0"]
```

ContainerProcess の ID は「インスタンス名`::`型名`:`Container のインスタンス名」の形をしていて、どの Container に結びついているかが ID からわかります。

`increment` を、同じ引数で 2 回呼び出してみましょう。

```sh
juiz container-process call "http://127.0.0.1:8000/container_process/example_container_hs_increment0::example_container_hs_increment:example_container_hs0" '{"arg1": 5}' -p
# => CapsulePtr((value:Value(5), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/example_container_hs_increment0::example_container_hs_increment:example_container_hs0" '{"arg1": 5}' -p
# => CapsulePtr((value:Value(10), option: []))
```

同じ `{"arg1": 5}` を渡しているのに、1 回目と 2 回目で結果が違います。
第 1 章の Process と違って、ContainerProcess の結果は引数だけでなく Container の状態にも左右されるからです。

## 2 つの ContainerProcess で Container を共有する

次は、`increment` が変えた値を `get` で読んでみます。
コマンドラインからは ContainerProcess を 1 つしか読み込めないので、「どの Container に、どの ContainerProcess を結びつけるか」を設定ファイルに書きます。
`my_juiz_hs/example_container.conf` を、次の内容で作ってください。

```yaml title="example_container.conf"
name: example_container
option:
  http_broker:
    start: true
    port: 8000
plugins:
  container_factories:
    example_container_hs:
      language: "haskell"
      path: "./build/plugins"
      processes:
        example_container_hs_increment:
          path: "./build/plugins"
        example_container_hs_get:
          path: "./build/plugins"
containers:
  - type_name: example_container_hs
    name: container0
    processes:
      - type_name: example_container_hs_increment
        name: increment0
      - type_name: example_container_hs_get
        name: get0
```

設定ファイルには、次のことが書かれています。

- Container の型と ContainerProcess の型を、どこから読み込むか(`plugins`)。型名から `libexample_container_hs.so`(macOS では `libexample_container_hs.dylib`)のようなファイル名を作って、`path` のディレクトリから探します。言語は `language: "haskell"` と書きます
- Container のインスタンス `container0` を 1 つ作ること(`containers`)
- `container0` に結びつけて、`increment` のインスタンス `increment0` と、`get` のインスタンス `get0` を作ること

設定ファイルの書き方は、次の第 3 章で詳しく扱います。ここでは「1 つの Container に、2 つの ContainerProcess がぶら下がっている」という形だけ押さえておいてください。

起動中の `juiz` を Ctrl+C で止めてから、設定ファイルを指定して起動し直します。

```sh
juiz -f example_container.conf -d
```

一覧を見ると、今度は ContainerProcess が 2 つあります(表示される順番は実行ごとに変わることがあります)。

```sh
juiz container-process list
# => ["http://127.0.0.1:8000/container_process/increment0::example_container_hs_increment:container0", "http://127.0.0.1:8000/container_process/get0::example_container_hs_get:container0"]
```

`get` で今の値を見てから、`increment` を 2 回呼び出し、もう一度 `get` で値を見てみましょう。

```sh
juiz container-process call "http://127.0.0.1:8000/container_process/get0::example_container_hs_get:container0" '{}' -p
# => CapsulePtr((value:Value(0), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/increment0::example_container_hs_increment:container0" '{"arg1": 5}' -p
# => CapsulePtr((value:Value(5), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/increment0::example_container_hs_increment:container0" '{"arg1": 5}' -p
# => CapsulePtr((value:Value(10), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/get0::example_container_hs_get:container0" '{}' -p
# => CapsulePtr((value:Value(10), option: []))
```

`increment` が変えた値を、別の ContainerProcess である `get` が読めています。2 つの ContainerProcess は、同じ Container を共有しています。

### ブラウザから呼び出す

第 1 章と同じく、Swagger UI(`http://127.0.0.1:8000/docs/`)からも呼び出せます。
`PATCH /api/container_process/call` を開いて、identifier には、`juiz container-process list` で表示された ID の先頭 `http://127.0.0.1:8000` を `core://core` に置き換えた ID を入力します。

- identifier: `core://core/container_process/get0::example_container_hs_get:container0`
- Request body: `{}`

## やってみよう

- `increment` に負の数(`{"arg1": -3}` など)を渡して、値が減ることを確かめてみましょう。
- `juiz` を Ctrl+C で止めてから起動し直し、`get` を呼び出してみましょう。値は最初に戻っています。状態は、動いている Container の中にだけあることがわかります。
- 値を 0 に戻す ContainerProcess(`example_container_hs_reset`)を足してみましょう。`get` と同じ形のファイルを作り、`writeIORef ref 0` で値を書き換えてから返します。`my-juiz-hs.cabal` と `example_container.conf` の両方に書き足すのを忘れないでください。

## まとめ

- 状態は Container に置きます。Container には「何を覚えておくか」だけを書き、処理は書きません。
- 状態を読み書きするのは、Container に結びついた ContainerProcess だけです。ContainerProcess は最初の引数で Container の状態を受け取ります。
- Haskell では、状態の型を別のモジュールに書き、Container と ContainerProcess のライブラリのどちらの `other-modules` にも入れます。書き換える値は `IORef` に入れます。
- 1 つの Container に、役割の違う ContainerProcess をいくつも結びつけられます。それらは同じ状態を共有します。
- ContainerProcess の結果は、引数だけでなく Container の状態にも左右されます。冪等な Process と、状態を扱う ContainerProcess を分けておくことで、状態がどこで変わるのかがはっきりします。

次の章では、この章で使った設定ファイルの書き方を学び、第 1 章の Process とこの章の Container を 1 つの設定ファイルでまとめて起動します。[設定ファイルでまとめて起動する](/ja/tutorial/config-file/) に進みましょう。
