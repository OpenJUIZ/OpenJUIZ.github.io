第 6 章では、別々に起動した juiz どうしを HTTP ブローカーでつなぎました。
juiz では、juiz どうしや外のプログラムとやりとりする通信の部分を **ブローカー** と呼び、設定ファイルで選べます。
この章では、HTTP の代わりに QUIC ブローカーを使って、第 6 章と同じように talker と listener をつなぎます。

<Aside type="tip" title="この章で学ぶこと">
- 通信方式はブローカーとして選べ、Process のコードは変えずにすむこと
- ID の先頭(`http://` や `qmp://`)が、どのブローカーを通るかを表すこと
- 1 つの juiz が、複数のブローカーを同時に持てること
</Aside>

<Aside type="caution" title="juiz 0.0.18 以降が必要です">
QUIC ブローカーは juiz 0.0.18 から `juiz` コマンドに組み込まれています。`cargo install juiz_app` で入れた場合も、pip の `juiz-cli` で入れた場合も、そのまま使えます。
版は `juiz --version` で確かめられます(古い版で正しく表示されないときは、`cargo install --list` や `pip show juiz-cli` で確かめてください)。0.0.17 以前では、QUIC ブローカーを juiz のソースからビルドしてプラグインとして読み込む必要があります。
</Aside>

## QUIC ブローカーとは

QUIC は、UDP の上で動く通信方式で、暗号化された 1 つの接続の中で複数のやりとりを並行して行えます。
juiz の QUIC ブローカーは、QUIC の上でデータを MessagePack で送ります。ブローカーの種類名は `qmp`(QUIC + MessagePack)です。

HTTP ブローカーと比べると、次のような違いがあります。

| | HTTP ブローカー | QUIC ブローカー |
| --- | --- | --- |
| 種類名(ID の先頭) | `http` | `qmp` |
| ポート | 8000(TCP、使用中なら 8001, 8002, …) | 設定ファイルで指定(UDP、使用中なら起動に失敗) |
| データの形式 | JSON | MessagePack |
| 外のツールからの利用 | Swagger UI や curl から呼べる | juiz どうしで使う |
| `juiz` への組み込み | 組み込み済み | 組み込み済み(0.0.18 以降) |

<Aside type="note">
QUIC ブローカーは起動のたびに自己署名の証明書を作り、つなぐ側は証明書を検証しません。通信は暗号化されますが、相手が本物かどうかは確かめないので、信頼できるネットワークの中で使ってください。
また、送れるのは数値や文字列などの値だけで、画像は送れません。
</Aside>

## 設定ファイルを用意する

QUIC ブローカーは `juiz` コマンドに組み込まれているので、設定ファイルの `brokers` に書くだけで実体化できます。
サンプル集のルートに、次の 2 つのファイルを作ります。どの言語でも同じ内容です。

listener 用の `listener_qmp.conf` は、QUIC ブローカーを UDP の 5000 番で待ち受けさせます。

```yaml title="listener_qmp.conf"
name: listener_qmp
brokers:
  - type_name: qmp
    name: qmp0
    port: 5000
```

<details>
<summary>ファイル全体を見る(Process も設定ファイルに書く場合)</summary>

この章では Process をコマンドラインの `--process` で読み込み、設定ファイルにはブローカーだけを書いています。Process もブローカーも 1 つの設定ファイルに書くと、次のようになります。`listener_qmp_full.conf` という名前で保存した場合は、`juiz -f listener_qmp_full.conf -d` だけで、このあとの「listener を起動する」と同じ juiz が動きます。ファイル名の拡張子を書かないので、OS ごとに書き分ける必要もありません。

talker 用の `talker_qmp.conf` は、名前とポート番号だけが違います。HTTP ブローカーと違って、QUIC ブローカーはポートが使用中でも自動ではずれず、juiz の起動に失敗します。juiz ごとに別の番号を書いてください。

```yaml title="talker_qmp.conf"
name: talker_qmp
brokers:
  - type_name: qmp
    name: qmp0
    port: 5001
```

<details>
<summary>ファイル全体を見る(Process も設定ファイルに書く場合)</summary>

## QUIC で呼び出す

call も同じです。`qmp://` の ID を指定すると、QUIC ブローカーを通って呼び出します。

<Tabs syncKey="lang">
<TabItem label="Rust">

```sh
juiz process call "qmp://127.0.0.1:5001/process/talker0::talker" '{}' -p
# => CapsulePtr((value:Value("Hello World"), option: [function_name:call,class_name:process,]))
```

</TabItem>
<TabItem label="Python">

```sh
juiz process call "qmp://127.0.0.1:5001/process/talker_python0::talker_python" '{}' -p
# => CapsulePtr((value:Value("Hello, World!"), option: [function_name:call,class_name:process,]))
```

</TabItem>
<TabItem label="C++">

```sh
juiz process call "qmp://127.0.0.1:5001/process/talker_cpp0::talker_cpp" '{}' -p
# => CapsulePtr((value:Value("Hello, Juiz!"), option: [function_name:call,class_name:process,]))
```

</TabItem>
</Tabs>

HTTP ブローカーで呼び出したときは `option: []` でしたが、QUIC ブローカーを通すと `option` に `function_name` と `class_name` が入って返ってきます。返ってくる値(`value`)は同じです。`option` の中の並び順は、実行するたびに入れ替わることがあります。

## やってみよう

- 第 6 章の `talker_ec.conf` に、`talker_qmp.conf` と同じ `brokers` を書き足して起動してみましょう。`juiz -s qmp://127.0.0.1:5001 ec list` で EC の ID を調べ、`juiz -s qmp://127.0.0.1:5001 ec start <ID>` で開始できます。
- つなぐ先だけを `http://127.0.0.1:8000/...` の ID に変えてつないでみましょう。listener は 1 つの juiz の中で両方のブローカーを持っているので、どちらの ID でも値が届きます。
- だれも待ち受けていないポートに `juiz -s qmp://127.0.0.1:5002 process list` と問い合わせてみましょう。QUIC は UDP なのでつながらないことがすぐにはわからず、しばらく待ってから `connecting to qmp broker '127.0.0.1:5002' (127.0.0.1:5002) timed out` というエラーになります。

## まとめ

- juiz の通信の部分はブローカーで、HTTP ブローカーのほかに QUIC ブローカー(`qmp`)を選べます。どちらも `juiz` コマンドに組み込まれていて、設定ファイルの `brokers` で実体化します。
- ID の先頭(`http://` や `qmp://`)が、どのブローカーを通るかを表します。`juiz connection create` や `juiz process call` は、ID を変えるだけで QUIC を使います。
- 1 つの juiz は複数のブローカーを同時に持てます。同じ Process に、ブローカーごとの ID があります。
- Process のコードは、どのブローカーで呼ばれるのかを知りません。だから通信方式を変えても、Process はそのまま使えます。
- 同じマシンの別プロセスへ画像などを速く渡すときは、IPC ブローカー(`ipc`)も使えます(juiz 0.0.26 以降)。使い分けは[ブローカーの選び方と大きなデータ](/ja/guides/large-data/)を見てください。

次の章では、Process の引数と戻り値にデータ型を付け、言語の違う Process どうしを型付きでつなぎます。[データ型: 型を決めて言語をまたいでつなぐ](/ja/tutorial/datatype/) に進みましょう。
