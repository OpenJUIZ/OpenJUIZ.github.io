この章では、`juiz pkg create` で Haskell(cabal)のプロジェクトの雛形を作り、その中の「2 つの数を足して返す」Process をビルドして動かします。
まず本体の Process のコードを読み、それから動かして、ブラウザとターミナルから呼び出します。最後に、雛形のほかのファイルを読みます。

<Aside type="tip" title="この章で学ぶこと">
- `juiz pkg create` で、Process を書く cabal のプロジェクトの雛形を作る方法
- 雛形の中身(`cabal.project`・`.cabal`・`src/MyJuiz.hs`・`app/app.conf`・`scripts/`)の読み方
- Process は、引数を受け取って結果を返す冪等な関数であること
- Process には「型名」と「インスタンス名」があること
- 外から Process を呼び出して結果を受け取る使い方(call)
</Aside>

<Aside type="note" title="Windows では">
Haskell のチュートリアルは Linux と macOS の手順で書いています。`juiz pkg create` の Haskell の雛形も、Windows では作れますが、そのままではビルドできません。
Windows で Haskell の部品を書く方法は、[言語ごとのパッケージの「Haskell」](/ja/getting-started/packages/#haskell) の「Windows」タブを見てください。
</Aside>

## 準備

次のものを用意してください(Linux・macOS)。

- `juiz` コマンド。[インストール](/ja/getting-started/install/) の、pip と cargo のどちらの入れ方でもかまいません
- GHC 9.6 以降と cabal。[GHCup](https://www.haskell.org/ghcup/) で入れられます
- `juiz` と同じ版の libjuiz_sdk
- `juiz` と同じ版の juiz のソース(Haskell 用のライブラリ hsjuiz を使うため)

Haskell の Process は、hsjuiz(juiz の Haskell 用のライブラリ)を使って書き、libjuiz_sdk(juiz と値を受け渡す関数の共有ライブラリ)にリンクしてビルドします。
hsjuiz は 0.2.6 から Hackage にもありますが([言語ごとのパッケージ](/ja/getting-started/packages/#haskell))、この章では juiz のソースを `juiz` と同じ版のタグで取得し、その中の `bindings/hsjuiz` を使います。`cabal update` が要らず、Hackage に無い版でも同じ手順で使えます。

`juiz` の版を確かめてから、同じ版の libjuiz_sdk を `~/.juiz/sdk/<版>` に展開し、juiz のソースを `~/juiz-<版>` に取得します(手でダウンロードする方法は [言語ごとのパッケージ](/ja/getting-started/packages/#c-と-haskell-の共通-libjuiz_sdk) にあります)。

## 雛形を作る

作業用のディレクトリで、次のコマンドを打ちます。

```sh
juiz pkg create my_juiz -b haskell -t process
```

| 部分 | 意味 |
| --- | --- |
| `my_juiz` | プロジェクトの名前です。同じ名前のディレクトリが作られ、型名の頭にもなります。英小文字で始まり、英小文字・数字・`_` だけが使えます |
| `-b haskell` | 使う言語です(`rust` / `python` / `cpp` / `haskell`) |
| `-t process` | 入れる型の種類です。`process` では Process を 1 つだけ入れます。省略すると Container も入りますが、この章では Process だけから始めます |

作ると、次に打つコマンドが表示されます(hsjuiz のソースと libjuiz_sdk は準備で用意したので、ここに表示される `git clone` と `curl` は飛ばしてかまいません)。

```text
Created my_juiz (haskell, process) in ./my_juiz  [hsjuiz 0.2.11]

Next steps:
  cd my_juiz
  # once: get hsjuiz 0.2.11 (the juiz source) in /home/me/juiz-0.2.11/bindings/hsjuiz
  git clone --depth 1 --branch v0.2.11 https://github.com/OpenJUIZ/juiz.git ~/juiz-0.2.11
  # once: put libjuiz_sdk 0.2.11 in /home/me/.juiz/sdk/0.2.11
  curl -fsSL https://raw.githubusercontent.com/OpenJUIZ/juiz/main/scripts/install-juiz-sdk.sh | sh -s -- 0.2.11
  scripts/dev.sh                  # build and put the plugin in app/plugins/<target>/
  juiz -f app/app.conf -d         # start (keep it running)
  ...
```

`/home/me` の所には、自分のホームディレクトリが表示されます(macOS では `/Users/me` のようになります)。
準備の前に雛形を作った場合は、hsjuiz と libjuiz_sdk が見つからないという警告も表示されますが、雛形はそのまま使えます。あとから用意してください。

以降のコマンドは、すべて `my_juiz` で実行します。

```sh
cd my_juiz
```

## プロジェクトの形

雛形には、次のファイルが入っています。

<FileTree>
- my_juiz/
  - cabal.project hsjuiz と libjuiz_sdk の場所
  - my-juiz.cabal ビルドの設定
  - src/
    - MyJuiz.hs Process のコード
  - app/
    - app.conf 起動の設定ファイル
    - juizapp.yaml 配布用のパッケージ(.juizapp)の情報
  - scripts/
    - dev.sh ビルドして app/plugins/ に置く
    - pack.sh 配布用のパッケージを作る
    - bundle-plugin-deps.sh pack.sh が使う
  - README.md この雛形の使い方(英語)
  - .gitignore
</FileTree>

juiz では、Process を共有ライブラリ(`.so`・`.dylib`)としてビルドし、`juiz` コマンドがそれをプラグインとして読み込みます。
雛形では、`src/MyJuiz.hs` に書いた型をまとめて 1 つの共有ライブラリにし、`app/app.conf` に書いたとおりに読み込んで起動します。
まず、開発の本体である Process のコードから読みましょう。

## Process のコード: src/MyJuiz.hs

```haskell title="src/MyJuiz.hs"
{-# LANGUAGE OverloadedStrings #-}
{-# LANGUAGE TemplateHaskell #-}
module MyJuiz () where

import Juiz

-- | The manifest of the whole Component (the types in this plugin)
my_juiz_component :: ComponentManifest
my_juiz_component = componentManifest "my_juiz"
  & description "my_juiz: a juiz component"

-- | Process my_juiz_add
my_juiz_add_manifest :: ProcessManifest
my_juiz_add_manifest = processManifest "my_juiz_add"
  & description "Returns a + b."
  & addIntArg "a" "the first value" 0
  & addIntArg "b" "the second value" 0

my_juiz_add :: Int64 -> Int64 -> Int64
my_juiz_add a b = a + b

juizComponent 'my_juiz_component
  [ componentProcess 'my_juiz_add 'my_juiz_add_manifest
  ]
```

ファイルの先頭の説明のコメントは省いています。

| 部分 | 意味 |
| --- | --- |
| `LANGUAGE` の 2 行 | 文字列リテラルを `Text` として使う `OverloadedStrings` と、最後の `juizComponent` が使う `TemplateHaskell` を有効にします |
| `import Juiz` | hsjuiz を読み込みます |
| `my_juiz_component` | このライブラリ(Component)の名前と説明です |
| `my_juiz_add_manifest` | Process の説明書(マニフェスト)です。`processManifest "my_juiz_add"` の文字列が Process の**型名**になります |
| `addIntArg "a" "the first value" 0` | 整数の引数 `a` を宣言します。説明と既定値(0)も書きます。呼び出すときに省いた引数には、既定値が使われます |
| `my_juiz_add :: Int64 -> Int64 -> Int64` | Process の本体です。引数は、マニフェストで宣言した順に渡されます。ふつうの純粋な関数で書けます |
| `juizComponent 'my_juiz_component [...]` | 関数とマニフェストを組にして、`juiz` から読み込めるように公開します。`componentProcess` で Process を並べます |

C++ と同じく、Haskell では型名と引数(名前・説明・既定値)をマニフェストに自分で書きます。

雛形では、複数の型を 1 つのライブラリにまとめる **Component** という形で書かれています。
この章では Process が 1 つだけですが、第 2 章で Container を同じファイルに足していきます。Component については第 5 章で詳しく扱います。

## Process は冪等な関数

`my_juiz_add` は、引数を受け取って結果を返すだけです。
外部の状態を読み書きしないので、同じ引数を渡せばいつも同じ結果が返ります(冪等)。
Haskell では、型 `Int64 -> Int64 -> Int64` がそのことを表しています(`IO` が付いていません)。
この性質のおかげで、Process はテストしやすく、あとでつないだり別のマシンに置いたりしても振る舞いが変わりません。

## ビルドする

`scripts/dev.sh` でビルドします。

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
scripts/dev.sh
# => ...
#    app/plugins/x86_64-unknown-linux-gnu/libmy_juiz.so
```

</TabItem>
<TabItem label="macOS">

```sh
scripts/dev.sh
# => ...
#    app/plugins/aarch64-apple-darwin/libmy_juiz.dylib
```

Intel の Mac では、`aarch64-apple-darwin` の所が `x86_64-apple-darwin` になります。

</TabItem>
</Tabs>

`scripts/dev.sh` は、`cabal build all` でビルドし、できあがった共有ライブラリを `app/plugins/<ターゲット>/` に写します。
`<ターゲット>` は、`x86_64-unknown-linux-gnu` のような「どの CPU・OS 向けか」を表す名前で、`juiz pkg target` で表示できます。
初回は hsjuiz も一緒にビルドするので、少し時間がかかります。

`cabal.project` に書かれた場所が違うと、hsjuiz や libjuiz_sdk が見つからずに `cabal build` が止まります。そのときは、準備で用意した場所と版を確かめてください。

<Aside type="caution">
できあがったプラグインは、`dist-newstyle` の中にある hsjuiz の共有ライブラリを参照しています。
`dist-newstyle` を消したり GHC を切り替えたりしたときは、`scripts/dev.sh` をもう一度実行してください。
</Aside>

<Aside type="note" title="macOS でリンクに失敗するとき">
選んでいる Xcode より新しい Command Line Tools が入っていると、GHC のリンクが `tapi error: ... unknown architecture` で失敗することがあります。
`DEVELOPER_DIR=/Library/Developer/CommandLineTools scripts/dev.sh` のように、Command Line Tools のリンカでビルドしてください([issue #143](https://github.com/OpenJUIZ/juiz/issues/143))。
</Aside>

## 動かす

設定ファイル `app/app.conf` を `-f` で渡して、`juiz` を起動します。

```sh
juiz -f app/app.conf -d
```

| オプション | 意味 |
| --- | --- |
| `-f <ファイル>` | 設定ファイルを読み込み、そこに書かれたとおりにプラグインを読み込んで、インスタンスを作る |
| `-d` | 起動したまま待機する(Ctrl+C で終了) |

起動すると、`juiz 管理画面: http://localhost:8000/ui/` と表示されます。HTTP ブローカーが 8000 番ポートで待ち受けています。

## ブラウザから呼び出す

`juiz` を起動したまま、ブラウザで管理画面 `http://localhost:8000/ui/` を開きます。次のような画面が出ます。

![管理画面。左に「処理 Process」の下の my_juiz_add0、中央の図に my_juiz_add0 の楕円が描かれている](../../../../../assets/tutorial-web-ui/first-process-top.png)

画面は 3 つの部分に分かれています。

- **左の一覧**: 動いているものの一覧です。「処理 Process」の下に、インスタンス `my_juiz_add0` が型名 `my_juiz_add` と並んで出ています。
- **中央の図**: 系の図です。Process は楕円で描かれ、大きな字がインスタンス名、小さな字が型名です。
- **右の欄**: 選んだものの性質(詳しい情報)が出ます。まだ何も選んでいないので空です。

左の一覧か中央の図で `my_juiz_add0` をクリックすると、右の欄に Process の情報が出ます。
右の欄を下へスクロールすると「呼び出す」という見出しがあり、引数 `a`・`b` の入力欄が並んでいます。
`a` に `1`、`b` に `2` を入れて「呼び出す」ボタンを押してください。下の「結果」に `3` が出れば成功です。

![右の欄の拡大。引数の表(a と b、型 Int、既定値 0)、呼び出すの欄に a=1・b=2、結果に 3](../../../../../assets/tutorial-web-ui/first-process-call.png)

右の欄のほかの部分も見ておきましょう。

- 「引数」の表には、引数の名前・型・既定値が並んでいます。既定値は、呼び出すときに省いた引数に使われる値で、コードの `default` に書いたものです(「拘束値」は第 3 章で扱います)。
- 「既定値に戻す」を押すと、入力欄が既定値(`0`)に戻ります。「JSON で編集」では、引数を JSON でまとめて書けます。
- 上のほうの「基本」には、型名と、この Process の識別子(ID)が出ています。

値を変えて、何度か呼び出してみてください。同じ引数なら、何度呼んでも同じ結果が返ります。
管理画面のほかの使い方は [ガイドの「管理画面」](/ja/guides/web-ui/) にあります。

## ターミナルから呼び出す

ブラウザでしたことは、ターミナルからもできます。`juiz` を起動したまま、別のターミナルを開いて `my_juiz` に移り、Process を呼び出してみます。
まず、動いている Process の一覧を見ます。

```sh
juiz process list
# => ["http://127.0.0.1:8000/process/my_juiz_add0::my_juiz_add"]
```

表示された URL が、この Process の **ID** です。
`http://127.0.0.1:8000` は Process がいる場所(ブローカー)、`process/` の後ろは「インスタンス名`::`型名」を表しています。
[ネームスペース](/ja/guides/namespace/)を使うと、インスタンス名の前に `robot1/` のようにネームスペースが入ります。使わなければ上のとおりです。

この ID と引数を指定して、Process を呼び出します(call)。引数は JSON で渡します。

```sh
juiz process call "http://127.0.0.1:8000/process/my_juiz_add0::my_juiz_add" '{"a": 1, "b": 2}' -p
# => CapsulePtr((value:Value(3), option: []))
```

`1` と `2` を渡して `3` が返ってきました。`-p` は結果を表示するオプションです。
引数を省くと、既定値(`a` も `b` も `0`)が使われます。`'{"a": 5}'` を渡すと `5` が返ります。
何度呼び出しても、同じ引数なら同じ結果が返ることも確かめてみてください。

`juiz` コマンドも管理画面も、HTTP で同じ API を呼んでいるだけです。
つまり、HTTP を話せるプログラムなら、どの言語からでも Process を呼び出して結果を受け取れます。
これが、juiz をサーバー・クライアントのように使う **call** という使い方です。

## 雛形のほかのファイルを読む

Process のコードのほかに、雛形にはビルドと起動のためのファイルが入っています。

### ビルドの設定: cabal.project と my-juiz.cabal

`cabal.project` には、一緒にビルドする hsjuiz と、libjuiz_sdk の場所が書かれています。

```txt title="cabal.project"
packages: . /home/me/juiz-0.2.11/bindings/hsjuiz

active-repositories: :none

package hsjuiz
  extra-lib-dirs: /home/me/.juiz/sdk/0.2.11/lib
  ghc-options: -optl-Wl,-rpath,/home/me/.juiz/sdk/0.2.11/lib
```

コメントは省いています。`/home/me` の所は、雛形を作ったときに自分のホームディレクトリが書かれます。

| 部分 | 意味 |
| --- | --- |
| `packages` | 一緒にビルドするパッケージです。`.` はこのプロジェクト、もう 1 つは準備で取得した juiz のソースの hsjuiz です |
| `active-repositories: :none` | Hackage からパッケージを取りに行かないようにします。hsjuiz は GHC に付いてくるパッケージだけを使うので、`cabal update` をしなくてもビルドできます |
| `package hsjuiz` の `extra-lib-dirs` | hsjuiz がリンクする libjuiz_sdk の場所です |
| `package hsjuiz` の `ghc-options` | rpath です。Template Haskell を動かすときに、GHC が hsjuiz と一緒に libjuiz_sdk を読み込むために要ります。できあがったプラグインも、ここから libjuiz_sdk を探します |

**hsjuiz と libjuiz_sdk の版は、`juiz --version` で表示される版と同じにしてください。** 版が違うプラグインは、`juiz` が読み込めません。
雛形では、雛形を作った `juiz` と同じ版の場所が書かれています。`juiz` を新しい版にしたときは、同じ版のソースと libjuiz_sdk を用意して、この 3 か所の版を書き換えてください。

`my-juiz.cabal` には、共有ライブラリを作る `foreign-library` が書かれています。

```txt title="my-juiz.cabal"
cabal-version:      3.0
name:               my-juiz
version:            0.1.0
synopsis:           my_juiz: a juiz component
build-type:         Simple

foreign-library my_juiz
    type:             native-shared
    default-language: Haskell2010
    build-depends:    base >=4.18 && <5
                    , hsjuiz
    ghc-options:      -Wall -threaded
    if os(darwin)
        ghc-options:  -optl-Wl,-rpath,@loader_path
    else
        ghc-options:  -optl-Wl,-rpath,$ORIGIN
    hs-source-dirs:   src
    other-modules:    MyJuiz
```

| 部分 | 意味 |
| --- | --- |
| `foreign-library my_juiz` | ほかの言語から読み込める共有ライブラリを作ります。名前 `my_juiz` から、Linux では `libmy_juiz.so`、macOS では `libmy_juiz.dylib` ができます |
| `type: native-shared` | 共有ライブラリにします。`juiz` が読み込めるのはこの形式です |
| `build-depends` | 使うパッケージです。`base >=4.18` は GHC 9.6 以降を表します |
| `-threaded` | juiz は Process を別のスレッドから呼ぶので、スレッドを使える実行時システムにします |
| `-rpath` の行 | 配布用のパッケージ(.juizapp)にしたときに、プラグインの隣に置いたライブラリを探せるようにします |
| `other-modules: MyJuiz` | Process を書いたモジュールです |

### 起動の設定ファイル: app/app.conf

`juiz -f` に渡した設定ファイルです(先頭のコメントは省いています)。

```yaml title="app/app.conf"
"name": "my_juiz"
"option":
  "http_broker":
    "start": true
    "port": 8000
"plugins":
  "components":
    "my_juiz":
      "language": "haskell"
      "path": "plugins/{target}"
"processes":
  - "type_name": "my_juiz_add"
    "name": "my_juiz_add0"
```

設定ファイルは YAML で書きます。ここでは、大まかに次のことが書かれています。

- `option`: HTTP ブローカーを 8000 番ポートで立ち上げる
- `plugins`: `plugins/{target}` から、Component `my_juiz` のライブラリを Haskell のプラグインとして**読み込む**。`{target}` は動かしているマシンのターゲット名に置き換わるので、`scripts/dev.sh` が置いた `app/plugins/<ターゲット>/libmy_juiz.so` が読み込まれます(パスは、設定ファイルのあるディレクトリ `app/` からの相対です)
- `processes`: 読み込んだ型 `my_juiz_add` から、`my_juiz_add0` という名前の**インスタンスを作る**

ここで「読み込む」と「インスタンスを作る」が分かれていることに注目してください。
ライブラリを読み込むと、juiz は Process の**型**(作り方)を覚えます。`processes` に書くと、その型から名前の付いた**インスタンス**を作ります。
呼び出すときの ID に入っていた `my_juiz_add0` がインスタンス名、`my_juiz_add` が型名です。
同じ型から、名前の違うインスタンスをいくつも作ることもできます(第 3 章で扱います)。

### scripts と app/juizapp.yaml

`scripts/dev.sh` は、上で使ったビルド用のスクリプトです。
`scripts/pack.sh`・`scripts/bundle-plugin-deps.sh` と `app/juizapp.yaml` は、できあがった部品を `.juizapp` というファイル 1 つにまとめて配る(`juiz run` だけで動かせる)ためのものです。チュートリアルでは使いません。使い方は [アプリの配布(.juizapp)](/ja/guides/app-package/) にあります。

## やってみよう

- `src/MyJuiz.hs` を書き換えて、足す代わりに掛け算(`a * b`)を返すようにしてみましょう。`scripts/dev.sh` でビルドし直して `juiz` を起動し直すと、`{"a": 3, "b": 4}` に対して `12` が返ってくるはずです。
- `juiz pkg add process my_juiz_sub` を打つと、`src/MyJuiz.hs` と `app/app.conf` に Process `my_juiz_sub` が足されます(中身は `my_juiz_add` と同じ `a + b`)。足された関数を `a - b` に書き換え、ビルドし直して呼び出してみましょう。`juiz process list` に 2 つの Process が並びます。

## まとめ

- `juiz pkg create <名前> -b haskell` で、ビルド・起動・呼び出しまでそのまま通るプロジェクトの雛形を作れます。hsjuiz と libjuiz_sdk の場所も `juiz` の版にそろえて書かれます。
- Haskell の Process は、cabal の `foreign-library` で共有ライブラリとしてビルドし、`juiz` がプラグインとして読み込みます。雛形では `scripts/dev.sh` がビルドして `app/plugins/<ターゲット>/` に置きます。
- Process は、引数を受け取って結果を返すだけの冪等な関数です。Haskell では、型名と引数をマニフェストに書き、`juizComponent` で関数と組にします。
- juiz はライブラリを読み込んで Process の**型**を覚え、設定ファイルに書いたとおりに、そこから名前の付いた**インスタンス**を作ります。
- 動いている Process には URL の形をした ID があり、ID と引数を指定して外から呼び出せます(call)。
