この章では、`juiz pkg create` で C++(CMake)のプロジェクトの雛形を作り、その中の「2 つの数を足して返す」Process をビルドして動かします。
まず本体の Process のコードを読み、それから動かして、ブラウザとターミナルから呼び出します。最後に、雛形のほかのファイルを読みます。

<Aside type="tip" title="この章で学ぶこと">
- `juiz pkg create` で、Process を書く CMake のプロジェクトの雛形を作る方法
- 雛形の中身(`CMakeLists.txt`・`src/my_juiz.cpp`・`app/app.conf`・`scripts/`)の読み方
- Process は、引数を受け取って結果を返す冪等な関数であること
- Process には「型名」と「インスタンス名」があること
- 外から Process を呼び出して結果を受け取る使い方(call)
</Aside>

## 準備

次のものを用意してください(Linux・macOS・Windows)。

- `juiz` コマンド。[インストール](/ja/getting-started/install/) の、pip と cargo のどちらの入れ方でもかまいません
- CMake 3.16 以降と、C++17 対応のコンパイラ(Windows は Visual Studio 2022 か Build Tools for Visual Studio 2022 の「C++ によるデスクトップ開発」。2019 でも動作を確認しています)
- `juiz` と同じ版の libjuiz_sdk とヘッダ

C++ の Process は、libjuiz_sdk(juiz と値を受け渡す関数の共有ライブラリ)にリンクしてビルドします。
`juiz` の版を確かめてから、同じ版の libjuiz_sdk を `~/.juiz/sdk/<版>`(Windows は `%USERPROFILE%\.juiz\sdk\<版>`)に展開します(手でダウンロードする方法は [言語ごとのパッケージ](/ja/getting-started/packages/#c-と-haskell-の共通-libjuiz_sdk) にあります)。

## 雛形を作る

作業用のディレクトリで、次のコマンドを打ちます。

```sh
juiz pkg create my_juiz -b cpp -t process
```

| 部分 | 意味 |
| --- | --- |
| `my_juiz` | プロジェクトの名前です。同じ名前のディレクトリが作られ、型名の頭にもなります。英小文字で始まり、英小文字・数字・`_` だけが使えます |
| `-b cpp` | 使う言語です(`rust` / `python` / `cpp` / `haskell`) |
| `-t process` | 入れる型の種類です。`process` では Process を 1 つだけ入れます。省略すると Container も入りますが、この章では Process だけから始めます |

作ると、次に打つコマンドが表示されます(libjuiz_sdk は準備で入れたので、ここに表示される `curl ... install-juiz-sdk.sh` は飛ばしてかまいません)。

```text
Created my_juiz (cpp, process) in ./my_juiz  [libjuiz_sdk 0.3.2]

Next steps:
  cd my_juiz
  # once: put libjuiz_sdk 0.3.2 in ~/.juiz/sdk/0.3.2
  curl -fsSL https://raw.githubusercontent.com/OpenJUIZ/juiz/main/scripts/install-juiz-sdk.sh | sh -s -- 0.3.2
  scripts/dev.sh                  # build and put the plugin and libjuiz_sdk in app/plugins/<target>/
  juiz -f app/app.conf -d         # start (keep it running)
  ...
```

以降のコマンドは、すべて `my_juiz` で実行します。

```sh
cd my_juiz
```

## プロジェクトの形

雛形には、次のファイルが入っています。

<FileTree>
- my_juiz/
  - CMakeLists.txt ビルドの設定
  - src/
    - my_juiz.cpp Process のコード
  - app/
    - app.conf 起動の設定ファイル
    - juizapp.yaml 配布用のパッケージ(.juizapp)の情報
  - scripts/
    - dev.sh ビルドして app/plugins/ に置く(Windows は dev.ps1)
    - pack.sh 配布用のパッケージを作る(Windows は pack.ps1)
  - README.md この雛形の使い方(英語)
  - .gitignore
</FileTree>

juiz では、Process を共有ライブラリ(`.so`・`.dylib`・`.dll`)としてビルドし、`juiz` コマンドがそれをプラグインとして読み込みます。
雛形では、`src/my_juiz.cpp` に書いた型をまとめて 1 つの共有ライブラリにし、`app/app.conf` に書いたとおりに読み込んで起動します。
まず、開発の本体である Process のコードから読みましょう。

## Process のコード: src/my_juiz.cpp

```cpp title="src/my_juiz.cpp"
#include <cstdint>
#include <optional>

#include "juiz/juiz.h"

// Process my_juiz_add. The arguments are passed in the order they are added to the manifest
static auto my_juiz_add_manif = ProcessManifest("my_juiz_add")
    .description("Returns a + b.")
    .add_int_arg("a", "the first value", 0)
    .add_int_arg("b", "the second value", 0);
std::optional<int64_t> my_juiz_add(int64_t a, int64_t b) {
    return a + b;
}
COMPONENT_PROCESS_FACTORY(my_juiz_add_manif, my_juiz_add);

// The manifest of the whole Component (the types in this plugin)
auto my_juiz_component_manifest() {
    return ComponentManifest("my_juiz")
        .description("my_juiz: a juiz component")
        .add_process(my_juiz_add_manifest());
}
DEFINE_COMPONENT_MANIFEST_ENTRY_POINT(my_juiz_component_manifest)
```

ファイルの先頭のコメントは省いています。

| 部分 | 意味 |
| --- | --- |
| `#include "juiz/juiz.h"` | juiz の C++ ヘッダです。libjuiz_sdk に入っています |
| `my_juiz_add_manif` | Process の説明書(マニフェスト)です。`ProcessManifest("my_juiz_add")` の文字列が Process の**型名**になります |
| `.description(...)` | Process の説明です。管理画面などに表示されます |
| `.add_int_arg("a", "the first value", 0)` | 整数の引数 `a` を宣言します。説明と既定値(0)も書きます。呼び出すときに省いた引数には、既定値が使われます |
| `my_juiz_add(int64_t a, int64_t b)` | Process の本体です。引数は、マニフェストで宣言した順に渡されます |
| `std::optional<int64_t>` | 戻り値です。値を返せないときは `std::nullopt` を返すとエラーになります |
| `COMPONENT_PROCESS_FACTORY(...)` | マニフェストと本体を組にして、`juiz` から使えるようにします。マニフェストの関数 `my_juiz_add_manifest()` も、このマクロが作ります |
| `my_juiz_component_manifest()` | このライブラリに入っている型の一覧です。`ComponentManifest("my_juiz")` はライブラリの名前で、`.add_process(...)` で Process を並べます |
| `DEFINE_COMPONENT_MANIFEST_ENTRY_POINT(...)` | 型の一覧を、`juiz` が読み込めるように公開します |

Rust や Python と違い、C++ では型名と引数(名前・説明・既定値)をマニフェストに自分で書きます。

雛形では、複数の型を 1 つのライブラリにまとめる **Component** という形で書かれています(`COMPONENT_...` や `ComponentManifest` という名前はそのためです)。
この章では Process が 1 つだけですが、第 2 章で Container を同じファイルに足していきます。Component については第 6 章で詳しく扱います。

## Process は冪等な関数

`my_juiz_add` は、引数を受け取って結果を返すだけです。
外部の状態を読み書きしないので、同じ引数を渡せばいつも同じ結果が返ります(冪等)。
この性質のおかげで、Process はテストしやすく、あとでつないだり別のマシンに置いたりしても振る舞いが変わりません。

「このシステムではスクリプトの実行が無効になっているため…」と表示されたら、一度だけ `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` を実行してから、もう一度打ってください。

`scripts/dev.sh` は、cmake で `build` ディレクトリにビルドし、できあがった共有ライブラリ(プラグイン)と libjuiz_sdk を `app/plugins/<ターゲット>/` に写します。
`<ターゲット>` は、`x86_64-unknown-linux-gnu` のような「どの CPU・OS 向けか」を表す名前で、`juiz pkg target` で表示できます。
プラグインは隣に置いた libjuiz_sdk を使うので、この 2 つはいつも一緒に置きます。

`Could not find a configuration file for package "juiz_sdk"` や、版が合わないという表示が出たら、準備で libjuiz_sdk を展開した場所と版を確かめてください。

## 動かす

設定ファイル `app/app.conf` を `-f` で渡して、`juiz` を起動します。

```sh
juiz -f app/app.conf -d
```

| オプション | 意味 |
| --- | --- |
| `-f <ファイル>` | 設定ファイルを読み込み、そこに書かれたとおりにプラグインを読み込んで、インスタンスを作る |
| `-d` | 起動したまま待機する(Ctrl+C で終了) |

起動すると、`juiz 管理画面: http://localhost:8000/ui/` と表示されます。HTTP ブローカーが 8000 番ポートで待ち受けています。

## ブラウザから呼び出す

`juiz` を起動したまま、ブラウザで管理画面 `http://localhost:8000/ui/` を開きます。次のような画面が出ます。

![管理画面。左に「処理 Process」の下の my_juiz_add0、中央の図に my_juiz_add0 の楕円が描かれている](../../../../../assets/tutorial-web-ui/first-process-top.png)

画面は 3 つの部分に分かれています。

- **左の一覧**: 動いているものの一覧です。「処理 Process」の下に、インスタンス `my_juiz_add0` が型名 `my_juiz_add` と並んで出ています。
- **中央の図**: 系の図です。Process は楕円で描かれ、大きな字がインスタンス名、小さな字が型名です。
- **右の欄**: 選んだものの性質(詳しい情報)が出ます。まだ何も選んでいないので空です。

左の一覧か中央の図で `my_juiz_add0` をクリックすると、右の欄に Process の情報が出ます。
右の欄を下へスクロールすると「呼び出す」という見出しがあり、引数 `a`・`b` の入力欄が並んでいます。
`a` に `1`、`b` に `2` を入れて「呼び出す」ボタンを押してください。下の「結果」に `3` が出れば成功です。

![右の欄の拡大。引数の表(a と b、型 Int、既定値 0)、呼び出すの欄に a=1・b=2、結果に 3](../../../../../assets/tutorial-web-ui/first-process-call.png)

右の欄のほかの部分も見ておきましょう。

- 「引数」の表には、引数の名前・型・既定値が並んでいます。既定値は、呼び出すときに省いた引数に使われる値で、コードの `default` に書いたものです(「拘束値」は第 3 章で扱います)。
- 「既定値に戻す」を押すと、入力欄が既定値(`0`)に戻ります。「JSON で編集」では、引数を JSON でまとめて書けます。
- 上のほうの「基本」には、型名と、この Process の識別子(ID)が出ています。

値を変えて、何度か呼び出してみてください。同じ引数なら、何度呼んでも同じ結果が返ります。
管理画面のほかの使い方は [ガイドの「管理画面」](/ja/guides/web-ui/) にあります。

## ターミナルから呼び出す

ブラウザでしたことは、ターミナルからもできます。`juiz` を起動したまま、別のターミナルを開いて `my_juiz` に移り、Process を呼び出してみます。
まず、動いている Process の一覧を見ます。

```sh
juiz process list
# => ["http://127.0.0.1:8000/process/my_juiz_add0::my_juiz_add"]
```

表示された URL が、この Process の **ID** です。
`http://127.0.0.1:8000` は Process がいる場所(ブローカー)、`process/` の後ろは「インスタンス名`::`型名」を表しています。
[ネームスペース](/ja/guides/namespace/)を使うと、インスタンス名の前に `robot1/` のようにネームスペースが入ります。使わなければ上のとおりです。

この ID と引数を指定して、Process を呼び出します(call)。引数は JSON で渡します。

```sh
juiz process call "http://127.0.0.1:8000/process/my_juiz_add0::my_juiz_add" '{"a": 1, "b": 2}' -p
# => CapsulePtr((value:Value(3), option: []))
```

`1` と `2` を渡して `3` が返ってきました。`-p` は結果を表示するオプションです。
引数を省くと、既定値(`a` も `b` も `0`)が使われます。`'{"a": 5}'` を渡すと `5` が返ります。

<Aside type="caution" title="Windows PowerShell 5.1 で JSON を渡すとき">
Windows に最初から入っている Windows PowerShell 5.1 は、`'{"a": 1, "b": 2}'` の `"` を消して `juiz` に渡してしまいます。
`'{\"a\": 1, \"b\": 2}'` のように `"` の前に `\` を書いてください。PowerShell 7.3 以降では、上のとおりに書けば動きます。
</Aside>

何度呼び出しても、同じ引数なら同じ結果が返ることも確かめてみてください。

`juiz` コマンドも管理画面も、HTTP で同じ API を呼んでいるだけです。
つまり、HTTP を話せるプログラムなら、どの言語からでも Process を呼び出して結果を受け取れます。
これが、juiz をサーバー・クライアントのように使う **call** という使い方です。

## 雛形のほかのファイルを読む

Process のコードのほかに、雛形にはビルドと起動のためのファイルが入っています。

### ビルドの設定: CMakeLists.txt

```cmake title="CMakeLists.txt"
cmake_minimum_required(VERSION 3.16)
project(my_juiz VERSION 0.1.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

if(NOT CMAKE_BUILD_TYPE AND NOT CMAKE_CONFIGURATION_TYPES)
  set(CMAKE_BUILD_TYPE Release)
endif()

set(JUIZ_VERSION "0.3.2")
if(WIN32)
  file(TO_CMAKE_PATH "$ENV{USERPROFILE}/.juiz/sdk/${JUIZ_VERSION}" JUIZ_SDK_DEFAULT_DIR)
else()
  set(JUIZ_SDK_DEFAULT_DIR "$ENV{HOME}/.juiz/sdk/${JUIZ_VERSION}")
endif()
set(JUIZ_SDK_DIR "${JUIZ_SDK_DEFAULT_DIR}" CACHE PATH "libjuiz_sdk directory")
find_package(juiz_sdk ${JUIZ_VERSION} EXACT CONFIG REQUIRED PATHS "${JUIZ_SDK_DIR}" NO_DEFAULT_PATH)

add_library(my_juiz SHARED src/my_juiz.cpp)
target_link_libraries(my_juiz PRIVATE juiz_sdk::juiz_sdk)
set_target_properties(my_juiz PROPERTIES
  LIBRARY_OUTPUT_DIRECTORY "$<1:${CMAKE_BINARY_DIR}/plugins>"
  RUNTIME_OUTPUT_DIRECTORY "$<1:${CMAKE_BINARY_DIR}/plugins>")
juiz_sdk_bundle(my_juiz)
```

コメントは省いています。上から順に見ていきます。

| 部分 | 意味 |
| --- | --- |
| `cmake_minimum_required`・`project` | 使う CMake の版と、プロジェクトの名前・版です。言語は C++(`CXX`)だけです |
| `CMAKE_CXX_STANDARD 17` | juiz の C++ ヘッダは C++17 を使うので、C++17 でコンパイルします |
| `JUIZ_VERSION`・`JUIZ_SDK_DIR` | libjuiz_sdk を展開した場所です。雛形を作った `juiz` と同じ版が書かれています。別の場所に置いた場合は、`cmake -D JUIZ_SDK_DIR=<場所>`(`scripts/dev.sh` では環境変数 `JUIZ_SDK_DIR`)で変えられます |
| `find_package(juiz_sdk ...)` | `JUIZ_SDK_DIR` から libjuiz_sdk を探します。`EXACT` を付けているので、版が違えばここで止まって教えてくれます。見つかると `juiz_sdk::juiz_sdk` というターゲットができます |
| `add_library(my_juiz SHARED ...)` | 共有ライブラリとしてビルドします。`juiz` が読み込めるのはこの形式です。ファイル名は Linux では `libmy_juiz.so`、macOS では `libmy_juiz.dylib`、Windows では `my_juiz.dll` になります |
| `target_link_libraries(... juiz_sdk::juiz_sdk)` | libjuiz_sdk にリンクします。juiz のヘッダを使う設定も、このターゲットに入っています |
| `LIBRARY_OUTPUT_DIRECTORY`・`RUNTIME_OUTPUT_DIRECTORY` | できた共有ライブラリを `build/plugins` に置きます |
| `juiz_sdk_bundle(my_juiz)` | プラグインが、隣に置いた libjuiz_sdk を使うようにし、`build/plugins` に libjuiz_sdk を写します。`scripts/dev.sh` は、この 2 つを `app/plugins/<ターゲット>/` に写します |

**libjuiz_sdk の版は、`juiz --version` で表示される版と同じにしてください。** 版が違うプラグインは、`juiz` が読み込めません。
`juiz` を新しい版にしたときは、同じ版の libjuiz_sdk を入れ、`JUIZ_VERSION` の 1 行も書き換えてください。

### 起動の設定ファイル: app/app.conf

`juiz -f` に渡した設定ファイルです(先頭のコメントは省いています)。

```yaml title="app/app.conf"
"name": "my_juiz"
"option":
  "http_broker":
    "start": true
    "port": 8000
"plugins":
  "components":
    "my_juiz":
      "language": "c++"
      "path": "plugins/{target}"
"processes":
  - "type_name": "my_juiz_add"
    "name": "my_juiz_add0"
```

設定ファイルは YAML で書きます。ここでは、大まかに次のことが書かれています。

- `option`: HTTP ブローカーを 8000 番ポートで立ち上げる
- `plugins`: `plugins/{target}` から、Component `my_juiz` のライブラリを C++ のプラグインとして**読み込む**。`{target}` は動かしているマシンのターゲット名に置き換わるので、`scripts/dev.sh` が置いた `app/plugins/<ターゲット>/libmy_juiz.so` が読み込まれます(パスは、設定ファイルのあるディレクトリ `app/` からの相対です)
- `processes`: 読み込んだ型 `my_juiz_add` から、`my_juiz_add0` という名前の**インスタンスを作る**

ここで「読み込む」と「インスタンスを作る」が分かれていることに注目してください。
ライブラリを読み込むと、juiz は Process の**型**(作り方)を覚えます。`processes` に書くと、その型から名前の付いた**インスタンス**を作ります。
呼び出すときの ID に入っていた `my_juiz_add0` がインスタンス名、`my_juiz_add` が型名です。
同じ型から、名前の違うインスタンスをいくつも作ることもできます(第 3 章で扱います)。

### scripts と app/juizapp.yaml

`scripts/dev.sh`(Windows は `scripts\dev.ps1`)は、上で使ったビルド用のスクリプトです。
`scripts/pack.sh` と `app/juizapp.yaml` は、できあがった部品を `.juizapp` というファイル 1 つにまとめて配る(`juiz run` だけで動かせる)ためのものです。チュートリアルでは使いません。使い方は [アプリの配布(.juizapp)](/ja/guides/app-package/) にあります。

## やってみよう

- `src/my_juiz.cpp` を書き換えて、足す代わりに掛け算(`a * b`)を返すようにしてみましょう。`scripts/dev.sh` でビルドし直して `juiz` を起動し直すと、`{"a": 3, "b": 4}` に対して `12` が返ってくるはずです。
- `juiz pkg add process my_juiz_sub` を打つと、`src/my_juiz.cpp` と `app/app.conf` に Process `my_juiz_sub` が足されます(中身は `my_juiz_add` と同じ `a + b`)。足された関数を `a - b` に書き換え、ビルドし直して呼び出してみましょう。`juiz process list` に 2 つの Process が並びます。

## まとめ

- `juiz pkg create <名前> -b cpp` で、ビルド・起動・呼び出しまでそのまま通るプロジェクトの雛形を作れます。libjuiz_sdk の版も `juiz` にそろえて書かれます。
- C++ の Process は、libjuiz_sdk にリンクした共有ライブラリとしてビルドし、`juiz` がプラグインとして読み込みます。雛形では `scripts/dev.sh` がビルドして、libjuiz_sdk と一緒に `app/plugins/<ターゲット>/` に置きます。
- Process は、引数を受け取って結果を返すだけの冪等な関数です。C++ では、型名と引数をマニフェストに書きます。
- juiz はライブラリを読み込んで Process の**型**を覚え、設定ファイルに書いたとおりに、そこから名前の付いた**インスタンス**を作ります。
- 動いている Process には URL の形をした ID があり、ID と引数を指定して外から呼び出せます(call)。
