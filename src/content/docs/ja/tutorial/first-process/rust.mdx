この章では、`juiz pkg create` で Rust のプロジェクトの雛形を作り、その中の「2 つの数を足して返す」Process をビルドして動かします。
まず本体の Process のコードを読み、それから動かして、ブラウザとターミナルから呼び出します。最後に、雛形のほかのファイルを読みます。

<Aside type="tip" title="この章で学ぶこと">
- `juiz pkg create` で、Process を書く Cargo のプロジェクトの雛形を作る方法
- 雛形の中身(`Cargo.toml`・`src/lib.rs`・`app/app.conf`・`scripts/`)の読み方
- Process は、引数を受け取って結果を返す冪等な関数であること
- Process には「型名」と「インスタンス名」があること
- 外から Process を呼び出して結果を受け取る使い方(call)
</Aside>

## 準備

[インストール](/ja/getting-started/install/) の「cargo で入れる」の手順で、Rust と `juiz` コマンドを入れておいてください(Linux・macOS・Windows)。
Windows では PowerShell で進めます。OS によってコマンドが違うところは、タブで書き分けています。

```sh
juiz --version
# => juiz 0.3.4
```

`juiz pkg` は juiz 0.2.6 から使えます。版が古いときは、`cargo install juiz_app` で入れ直してください。

## 雛形を作る

作業用のディレクトリで、次のコマンドを打ちます。

```sh
juiz pkg create my_juiz -b rust -t process
```

| 部分 | 意味 |
| --- | --- |
| `my_juiz` | プロジェクトの名前です。同じ名前のディレクトリが作られ、型名の頭にもなります。英小文字で始まり、英小文字・数字・`_` だけが使えます |
| `-b rust` | 使う言語です(`rust` / `python` / `cpp` / `haskell`) |
| `-t process` | 入れる型の種類です。`process` では Process を 1 つだけ入れます。省略すると Container も入りますが、この章では Process だけから始めます |

作ると、次に打つコマンドが表示されます。

```text
Created my_juiz (rust, process) in ./my_juiz  [juiz_sdk =0.3.4]

Next steps:
  cd my_juiz
  scripts/dev.sh                  # build and put the plugin in app/plugins/<target>/
  juiz -f app/app.conf -d         # start (keep it running)
  ...
```

以降のコマンドは、すべて `my_juiz` で実行します。

```sh
cd my_juiz
```

## プロジェクトの形

雛形には、次のファイルが入っています。

<FileTree>
- my_juiz/
  - Cargo.toml クレートの設定
  - src/
    - lib.rs Process のコード
  - app/
    - app.conf 起動の設定ファイル
    - juizapp.yaml 配布用のパッケージ(.juizapp)の情報
  - scripts/
    - dev.sh ビルドして app/plugins/ に置く(Windows は dev.ps1)
    - pack.sh 配布用のパッケージを作る(Windows は pack.ps1)
  - README.md この雛形の使い方(英語)
  - .gitignore
</FileTree>

juiz では、Process を共有ライブラリ(`.so`・`.dylib`・`.dll`)としてビルドし、`juiz` コマンドがそれをプラグインとして読み込みます。
雛形では、`src/lib.rs` に書いた型をまとめて 1 つの共有ライブラリにし、`app/app.conf` に書いたとおりに読み込んで起動します。
まず、開発の本体である Process のコードから読みましょう。

## Process のコード: src/lib.rs

```rust title="src/lib.rs"
use juiz_sdk::prelude::*;

#[juiz_component_process(
    description = "Returns a + b."
    arguments = { default = { a = 0 b = 0 } }
)]
fn my_juiz_add(a: i64, b: i64) -> JuizResult<i64> {
    Ok(a + b)
}

juiz_component_manifest!(
    component_name = "my_juiz"
    processes = [ my_juiz_add ]
);
```

ファイルの先頭のコメントと、末尾のテスト(`#[cfg(test)]` の部分)は省いています。

| 部分 | 意味 |
| --- | --- |
| `use juiz_sdk::prelude::*;` | Process を書くのに使うマクロや型(`juiz_component_process`・`JuizResult` など)をまとめて読み込みます |
| `#[juiz_component_process(...)]` | この関数を Process にします |
| `description` | Process の説明です。管理画面などに表示されます |
| `arguments = { default = { a = 0 b = 0 } }` | 引数の既定値です。呼び出すときに省いた引数には、この値が使われます |
| `fn my_juiz_add(a: i64, b: i64)` | 関数名 `my_juiz_add` が Process の**型名**、引数名 `a`・`b` がそのまま引数の名前になります |
| `-> JuizResult<i64>` | 戻り値です。成功したら `Ok(値)` を、失敗したら `Err(...)` を返します |
| `juiz_component_manifest!(...)` | このライブラリに入っている型の一覧です。`component_name` はライブラリの名前で、`processes` に Process の関数名を並べます |

Process 本体は、`a + b` を返すだけの短い関数です。juiz と値を受け渡す部分は、マクロが作ってくれます。

雛形では、複数の型を 1 つのライブラリにまとめる **Component** という形で書かれています(`juiz_component_*` という名前はそのためです)。
この章では Process が 1 つだけですが、第 2 章で Container を同じファイルに足していきます。Component については第 6 章で詳しく扱います。

`cargo test` で、末尾のテスト(`my_juiz_add` に 1 と 2 を渡して 3 が返ることを確かめるもの)を動かせます。

## Process は冪等な関数

`my_juiz_add` は、引数を受け取って結果を返すだけです。
外部の状態を読み書きしないので、同じ引数を渡せばいつも同じ結果が返ります(冪等)。
この性質のおかげで、Process はテストしやすく、あとでつないだり別のマシンに置いたりしても振る舞いが変わりません。

## ビルドする

`scripts/dev.sh` でビルドします。

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
scripts/dev.sh
# => ...
#    app/plugins/x86_64-unknown-linux-gnu/libmy_juiz.so
```

</TabItem>
<TabItem label="macOS">

```sh
scripts/dev.sh
# => ...
#    app/plugins/aarch64-apple-darwin/libmy_juiz.dylib
```

Intel の Mac では、`aarch64-apple-darwin` の所が `x86_64-apple-darwin` になります。

</TabItem>
<TabItem label="Windows">

```powershell
scripts\dev.ps1
# => ...
#    app\plugins\x86_64-pc-windows-msvc\my_juiz.dll
```

Windows では、ファイル名の先頭に `lib` が付きません。

<Aside type="caution" title="スクリプトの実行が禁止されているとき">
「このシステムではスクリプトの実行が無効になっているため…」と表示されたら、一度だけ `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` を実行してから、もう一度打ってください。
</Aside>

</TabItem>
</Tabs>

`scripts/dev.sh` は、`cargo build` でビルドし、できあがった共有ライブラリを `app/plugins/<ターゲット>/` に写します。
`<ターゲット>` は、`x86_64-unknown-linux-gnu` のような「どの CPU・OS 向けか」を表す名前で、`juiz pkg target` で表示できます。
初回は `juiz_sdk` とその依存クレートを取得してビルドするので、少し時間がかかります。

## 動かす

設定ファイル `app/app.conf` を `-f` で渡して、`juiz` を起動します。

```sh
juiz -f app/app.conf -d
```

| オプション | 意味 |
| --- | --- |
| `-f <ファイル>` | 設定ファイルを読み込み、そこに書かれたとおりにプラグインを読み込んで、インスタンスを作る |
| `-d` | 起動したまま待機する(Ctrl+C で終了) |

起動すると、`juiz 管理画面: http://localhost:8000/ui/` と表示されます。HTTP ブローカーが 8000 番ポートで待ち受けています。

## ブラウザから呼び出す

`juiz` を起動したまま、ブラウザで管理画面 `http://localhost:8000/ui/` を開きます。次のような画面が出ます。

![管理画面。左に「処理 Process」の下の my_juiz_add0、中央の図に my_juiz_add0 の楕円が描かれている](../../../../../assets/tutorial-web-ui/first-process-top.png)

画面は 3 つの部分に分かれています。

- **左の一覧**: 動いているものの一覧です。「処理 Process」の下に、インスタンス `my_juiz_add0` が型名 `my_juiz_add` と並んで出ています。
- **中央の図**: 系の図です。Process は楕円で描かれ、大きな字がインスタンス名、小さな字が型名です。
- **右の欄**: 選んだものの性質(詳しい情報)が出ます。まだ何も選んでいないので空です。

左の一覧か中央の図で `my_juiz_add0` をクリックすると、右の欄に Process の情報が出ます。
右の欄を下へスクロールすると「呼び出す」という見出しがあり、引数 `a`・`b` の入力欄が並んでいます。
`a` に `1`、`b` に `2` を入れて「呼び出す」ボタンを押してください。下の「結果」に `3` が出れば成功です。

![右の欄の拡大。引数の表(a と b、型 Int、既定値 0)、呼び出すの欄に a=1・b=2、結果に 3](../../../../../assets/tutorial-web-ui/first-process-call.png)

右の欄のほかの部分も見ておきましょう。

- 「引数」の表には、引数の名前・型・既定値が並んでいます。既定値は、呼び出すときに省いた引数に使われる値で、コードの `default` に書いたものです(「拘束値」は第 3 章で扱います)。
- 「既定値に戻す」を押すと、入力欄が既定値(`0`)に戻ります。「JSON で編集」では、引数を JSON でまとめて書けます。
- 上のほうの「基本」には、型名と、この Process の識別子(ID)が出ています。

値を変えて、何度か呼び出してみてください。同じ引数なら、何度呼んでも同じ結果が返ります。
管理画面のほかの使い方は [ガイドの「管理画面」](/ja/guides/web-ui/) にあります。

## ターミナルから呼び出す

ブラウザでしたことは、ターミナルからもできます。`juiz` を起動したまま、別のターミナルを開いて `my_juiz` に移り、Process を呼び出してみます。
まず、動いている Process の一覧を見ます。

```sh
juiz process list
# => ["http://127.0.0.1:8000/process/my_juiz_add0::my_juiz_add"]
```

表示された URL が、この Process の **ID** です。
`http://127.0.0.1:8000` は Process がいる場所(ブローカー)、`process/` の後ろは「インスタンス名`::`型名」を表しています。
[ネームスペース](/ja/guides/namespace/)を使うと、インスタンス名の前に `robot1/` のようにネームスペースが入ります(`process/robot1/my_juiz_add0::my_juiz_add`)。使わなければ上のとおりです。

この ID と引数を指定して、Process を呼び出します(call)。引数は JSON で渡します。

```sh
juiz process call "http://127.0.0.1:8000/process/my_juiz_add0::my_juiz_add" '{"a": 1, "b": 2}' -p
# => CapsulePtr((value:Value(3), option: []))
```

`1` と `2` を渡して `3` が返ってきました。`-p` は結果を表示するオプションです。
引数を省くと、既定値(`a` も `b` も `0`)が使われます。`'{"a": 5}'` を渡すと `5` が返ります。

<Aside type="caution" title="Windows PowerShell 5.1 で JSON を渡すとき">
Windows に最初から入っている Windows PowerShell 5.1 は、`'{"a": 1, "b": 2}'` の `"` を消して `juiz` に渡してしまいます。
`'{\"a\": 1, \"b\": 2}'` のように `"` の前に `\` を書いてください。PowerShell 7.3 以降では、上のとおりに書けば動きます。
</Aside>

何度呼び出しても、同じ引数なら同じ結果が返ることも確かめてみてください。

`juiz` コマンドも管理画面も、HTTP で同じ API を呼んでいるだけです。
つまり、HTTP を話せるプログラムなら、どの言語からでも Process を呼び出して結果を受け取れます。
これが、juiz をサーバー・クライアントのように使う **call** という使い方です。

## 雛形のほかのファイルを読む

Process のコードのほかに、雛形にはビルドと起動のためのファイルが入っています。

### クレートの設定: Cargo.toml

```toml title="Cargo.toml"
[package]
name = "my_juiz"
version = "0.1.0"
edition = "2021"
description = "my_juiz: a juiz component"
publish = false

[lib]
# cdylib: the plugin juiz loads (C ABI). rlib: for cargo test
crate-type = ["cdylib", "rlib"]

[dependencies]
# Same version as the juiz that made this skeleton (juiz --version)
juiz_sdk = "=0.3.4"
```

| 項目 | 意味 |
| --- | --- |
| `name` | クレートの名前です。ビルドしてできる共有ライブラリのファイル名になります。Linux では `libmy_juiz.so`、macOS では `libmy_juiz.dylib`、Windows では先頭に `lib` が付かず `my_juiz.dll` です |
| `[lib]` の `crate-type` | `"cdylib"` は、ほかの言語からも読み込める共有ライブラリ(C 形式の動的ライブラリ)です。`juiz` が読み込めるのはこの形式です。`"rlib"` は `cargo test` のために付いています |
| `juiz_sdk = "=0.3.4"` | Process を書くためのクレートと、その版です |

**`juiz_sdk` の版は、`juiz --version` で表示される版と同じにしておくのがおすすめです。** 雛形では、雛形を作った `juiz` と同じ版が `=` で固定して書かれています。
`juiz` を新しい版にしたときは、この 1 行も同じ版に書き換えてください。

### 起動の設定ファイル: app/app.conf

`juiz -f` に渡した設定ファイルです(先頭のコメントは省いています)。

```yaml title="app/app.conf"
"name": "my_juiz"
"option":
  "http_broker":
    "start": true
    "port": 8000
"plugins":
  "components":
    "my_juiz":
      "language": "rust"
      "path": "plugins/{target}"
"processes":
  - "type_name": "my_juiz_add"
    "name": "my_juiz_add0"
```

設定ファイルは YAML で書きます。ここでは、大まかに次のことが書かれています。

- `option`: HTTP ブローカーを 8000 番ポートで立ち上げる
- `plugins`: `plugins/{target}` から、Component `my_juiz` のライブラリを**読み込む**。`{target}` は動かしているマシンのターゲット名に置き換わるので、`scripts/dev.sh` が置いた `app/plugins/<ターゲット>/libmy_juiz.so` が読み込まれます(パスは、設定ファイルのあるディレクトリ `app/` からの相対です)
- `processes`: 読み込んだ型 `my_juiz_add` から、`my_juiz_add0` という名前の**インスタンスを作る**

ここで「読み込む」と「インスタンスを作る」が分かれていることに注目してください。
ライブラリを読み込むと、juiz は Process の**型**(作り方)を覚えます。`processes` に書くと、その型から名前の付いた**インスタンス**を作ります。
呼び出すときの ID に入っていた `my_juiz_add0` がインスタンス名、`my_juiz_add` が型名です。
同じ型から、名前の違うインスタンスをいくつも作ることもできます(第 3 章で扱います)。

### scripts と app/juizapp.yaml

`scripts/dev.sh`(Windows は `scripts\dev.ps1`)は、上で使ったビルド用のスクリプトです。
`scripts/pack.sh` と `app/juizapp.yaml` は、できあがった部品を `.juizapp` というファイル 1 つにまとめて配る(`juiz run` だけで動かせる)ためのものです。チュートリアルでは使いません。使い方は [アプリの配布(.juizapp)](/ja/guides/app-package/) にあります。

## やってみよう

- `src/lib.rs` を書き換えて、足す代わりに掛け算(`a * b`)を返すようにしてみましょう。`scripts/dev.sh` でビルドし直して `juiz` を起動し直すと、`{"a": 3, "b": 4}` に対して `12` が返ってくるはずです。
- `juiz pkg add process my_juiz_sub` を打つと、`src/lib.rs` と `app/app.conf` に Process `my_juiz_sub` が足されます(中身は `my_juiz_add` と同じ `a + b`)。足された関数を `a - b` に書き換え、ビルドし直して呼び出してみましょう。`juiz process list` に 2 つの Process が並びます。

## まとめ

- `juiz pkg create <名前> -b rust` で、ビルド・起動・呼び出しまでそのまま通るプロジェクトの雛形を作れます。`juiz_sdk` の版も `juiz` にそろえて書かれます。
- Rust の Process は、`crate-type` に `"cdylib"` を含むクレートとしてビルドし、`juiz` がプラグインとして読み込みます。雛形では `scripts/dev.sh` がビルドして `app/plugins/<ターゲット>/` に置きます。
- Process は、引数を受け取って結果を返すだけの冪等な関数です。`#[juiz_component_process]` を付けた関数の名前が型名になります。
- juiz はライブラリを読み込んで Process の**型**を覚え、設定ファイルに書いたとおりに、そこから名前の付いた**インスタンス**を作ります。
- 動いている Process には URL の形をした ID があり、ID と引数を指定して外から呼び出せます(call)。

次の章では、このプロジェクトにカウンタの Container を足して、状態を持つ部品の書き方を学びます。[状態を持つ: Container と ContainerProcess(Rust)](/ja/tutorial/container/rust/) に進みましょう。
