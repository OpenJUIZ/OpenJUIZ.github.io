ここまでは、Process も Container も ContainerProcess も、1 つの型ごとに別々のファイル(ライブラリ)として作ってきました。
第 3 章の設定ファイルでも、`plugins` に型を 1 つずつ並べて、それぞれのファイルを読み込ませていました。

実際に「このカメラを動かす部品一式」を誰かに渡すときに、ファイルがばらばらだと不便です。
この章では、Process・Container・ContainerProcess を 1 つのライブラリにまとめた **Component** を作り、設定ファイルから読み込みます。

<Aside type="tip" title="この章で学ぶこと">
- Component は、複数の Process・Container・ContainerProcess を 1 つにまとめた**配布の単位**であること
- Component の中の型は、これまでと同じ型名で、同じようにインスタンスを作れること
- `plugins` の `components` には、型ではなく Component の名前を 1 つ書けばよいこと
</Aside>

## サンプルを用意する

第 4 章でクローンしてビルドしたサンプル集をそのまま使います。Component のサンプルも、第 4 章のビルドで一緒にできあがっています。
まだの場合は、[第 4 章(Haskell)の「サンプルを用意する」](/ja/tutorial/connect/haskell/#サンプルを用意する) の手順を済ませてください。

この章で使う Component には、次のものが入っています。どれも、これまでの章で作ったものと同じ働きです。

| 種類 | 働き |
| --- | --- |
| Process | 引数に 1 を足して返す(第 1 章の `increment_process` と同じ) |
| Container | 整数値を 1 つ持つ(第 2 章のカウンタと同じ) |
| ContainerProcess | Container の値を読む・変える |

## Component のコードを読む

[`component/ExampleComponent.hs`](https://github.com/OpenJUIZ/juiz_examples_haskell/blob/main/component/ExampleComponent.hs)

```haskell
{-# LANGUAGE OverloadedStrings #-}
{-# LANGUAGE TemplateHaskell #-}
-- | 1 つのライブラリに Process・Container・ContainerProcess をまとめた Component (example_component_hs)。
--
-- 各要素の関数とマニフェストを書き、最後に juizComponent でまとめて公開する。
module ExampleComponent () where

import Juiz

component :: ComponentManifest
component = componentManifest "example_component_hs"
  & description "Haskell component example."

-- Process: arg1 に 1 を足して返す
incrementManifest :: ProcessManifest
incrementManifest = processManifest "example_component_hs_increment"
  & description "Adds 1 to arg1."
  & addIntArg "arg1" "value to be incremented" 1

increment :: Int64 -> Int64
increment arg1 = arg1 + 1

-- Container: 整数値を 1 つ保持する。
-- Component では Container と ContainerProcess が同じライブラリに入るので、状態の型を別のモジュールに分けなくてよい
newtype ComponentContainer = ComponentContainer (IORef Int64)

containerManif :: ContainerManifest
containerManif = containerManifest "example_component_hs_container"
  & description "Holds an integer value."
  & addIntArg "value" "initial value" 0

createContainer :: Int64 -> IO ComponentContainer
createContainer value = ComponentContainer <$> newIORef value

-- ContainerProcess: Container の値を返す
getManifest :: ProcessManifest
getManifest = containerProcessManifest "example_component_hs_container_get" "example_component_hs_container"
  & description "Returns the value of the container."

containerGet :: ComponentContainer -> IO Int64
containerGet (ComponentContainer ref) = readIORef ref

-- ContainerProcess: Container の値に arg1 を足す
incrementContainerManifest :: ProcessManifest
incrementContainerManifest =
  containerProcessManifest "example_component_hs_container_increment" "example_component_hs_container"
    & description "Adds arg1 to the value of the container."
    & addIntArg "arg1" "value to be added" 1

containerIncrement :: ComponentContainer -> Int64 -> IO Int64
containerIncrement (ComponentContainer ref) arg1 = atomicModifyIORef' ref (\v -> (v + arg1, v + arg1))

juizComponent 'component
  [ componentProcess 'increment 'incrementManifest
  , componentContainer 'createContainer 'containerManif
  , componentContainerProcess 'containerGet 'getManifest
  , componentContainerProcess 'containerIncrement 'incrementContainerManifest
  ]
```

各要素の関数とマニフェストは、第 1 章・第 2 章で単体として書いたときと同じ形です。変わるのは公開のしかただけです。

- 単体のときの `juizProcess`・`juizContainer`・`juizContainerProcess` の代わりに、最後の `juizComponent` で全部をまとめて公開します。
- `juizComponent` には、Component のマニフェスト(`componentManifest "example_component_hs"`、文字列が Component の名前)と、中に入れる要素の一覧を渡します。要素は `componentProcess`・`componentContainer`・`componentContainerProcess` に関数とマニフェストを組にして渡します。
- 1 つのモジュールにいくつもの型を入れるので、マニフェストは `incrementManifest` のように型ごとに名前を付けます。
- ContainerProcess がどの Container に結びつくかは、単体のときと同じく `containerProcessManifest` の 2 つ目の引数(Container の型名)で決まります。
- Container と ContainerProcess が同じライブラリに入るので、第 2 章のように状態の型を別のモジュールに分ける必要はありません。

ビルドは [`juiz-examples-haskell.cabal`](https://github.com/OpenJUIZ/juiz_examples_haskell/blob/main/juiz-examples-haskell.cabal) の `foreign-library` 1 つです。

```txt
foreign-library example_component_hs
    import:           plugin
    type:             native-shared
    hs-source-dirs:   component
    other-modules:    ExampleComponent
```

1 つの共有ライブラリができます。ファイル名は Linux では `build/plugins/libexample_component_hs.so`、macOS では `build/plugins/libexample_component_hs.dylib` です。

これまで型ごとに分かれていたものが、Component では1 つのライブラリに入っています。
それぞれの Process や ContainerProcess の中身は、これまでと変わりません。Process は冪等な関数のまま、状態に触れるのは ContainerProcess だけ、という考え方もそのままです。

## 設定ファイルを読む

[`example_component.conf`](https://github.com/OpenJUIZ/juiz_examples_haskell/blob/main/example_component.conf)

```yaml
name: example_component
option:
  http_broker:
    start: true
    port: 8000
plugins:
  components:
    example_component_hs:
      language: "haskell"
      path: "./build/plugins"
processes:
  - type_name: example_component_hs_increment
    name: proc0
containers:
  - type_name: example_component_hs_container
    name: container0
    value: 100
    processes:
      - type_name: example_component_hs_container_increment
        name: increment0
      - type_name: example_component_hs_container_get
        name: get0
```

第 3 章の設定ファイルと比べてみましょう。

### plugins: Component を 1 つ書く

```yaml
plugins:
  components:
    example_component_hs:
      language: "haskell"
      path: "./build/plugins"
```

第 3 章では、`process_factories` と `container_factories` に型を 1 つずつ書き、ContainerProcess も Container の下に 1 つずつ書いていました。
Component では、`components` に **Component の名前を 1 つ**書くだけです。キーの名前から読み込むファイルが決まるのは、第 3 章と同じです。

Component 名 `example_component_hs` なら、`./build/plugins` の中の `libexample_component_hs.so`(macOS では `libexample_component_hs.dylib`)が読み込まれます。設定ファイルには拡張子を書かないので、同じ設定ファイルがどの OS でも使えます。

この 1 行で、Component の中にある Process・Container・ContainerProcess の型が、すべて読み込まれます。

### processes と containers: いつもどおり作る

`processes` と `containers` の書き方は、第 3 章とまったく同じです。`type_name` に Component の中の型名を書き、`name` にインスタンスの名前を書きます。
Container の初期値を渡せるのも同じです。

型がどのファイルから来たのかは、インスタンスを作る側には関係ありません。
Component は「型をまとめて配る」ためのもので、作ったインスタンスは、別々のファイルから読み込んだときと同じように動きます。

## 動かす

設定ファイルを `-f` で渡して起動します。

```sh
juiz -f example_component.conf -d
```

## 外から呼び出す

`juiz` を起動したまま別のターミナルを開き、一覧を見てみます。

```sh
juiz process list
# => ["http://127.0.0.1:8000/process/proc0::example_component_hs_increment"]
juiz container list
# => ["http://127.0.0.1:8000/container/container0::example_component_hs_container"]
juiz container-process list
# => ["http://127.0.0.1:8000/container_process/get0::example_component_hs_container_get:container0", "http://127.0.0.1:8000/container_process/increment0::example_component_hs_container_increment:container0"]
```

1 つのファイルから読み込んだ型で、Process・Container・ContainerProcess のインスタンスがそろってできています。ID の形も、これまでの章とまったく同じです。
それぞれを呼び出してみましょう。

```sh
juiz process call "http://127.0.0.1:8000/process/proc0::example_component_hs_increment" '{"arg1": 3}' -p
# => CapsulePtr((value:Value(4), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/get0::example_component_hs_container_get:container0" '{}' -p
# => CapsulePtr((value:Value(100), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/increment0::example_component_hs_container_increment:container0" '{"arg1": 5}' -p
# => CapsulePtr((value:Value(105), option: []))
juiz container-process call "http://127.0.0.1:8000/container_process/get0::example_component_hs_container_get:container0" '{}' -p
# => CapsulePtr((value:Value(105), option: []))
```

Process は引数に 1 を足して返し、ContainerProcess は Container の値を変えたり読んだりします。
呼び出す側から見ると、第 1 章〜第 3 章で別々のファイルから作ったものと区別がつきません。

## Component は配布の単位

ここまでで見たように、Component にまとめても、Process や Container の働きや使い方は何も変わりません。変わるのは**ファイルの束ね方**だけです。

- **作る人**は、関連する Process・Container・ContainerProcess を 1 つのプロジェクトで書き、1 つのライブラリとして配れます。たとえばカメラなら、カメラを開いて持っておく Container、画像を読む ContainerProcess、画像を変換する Process を 1 つの Component にできます。
- **使う人**は、`plugins` の `components` に 1 行書くだけで、中の型を全部使えるようになります。どの型を何個作るかは、これまでどおり `processes` と `containers` で自由に決められます。

つまり、Process・Container・ContainerProcess が「動かすときの単位」であるのに対して、Component は「配るときの単位」です。

## やってみよう

- `processes` に `example_component_hs_increment`のインスタンスをもう 1 つ書き足してみましょう。Component から読み込んだ型からも、第 3 章と同じように、いくつでもインスタンスを作れます。
- `containers` にもう 1 つ Container(たとえば `container1`)と、それに結びつく ContainerProcess を書き足してみましょう。`container0` と `container1` は別々の値を持ちます。
- 第 4 章の `connections` と `ecs` を書き足して、1 つ目の Process の出力を、書き足した 2 つ目の Process の `arg1` につないでみましょう。Component から読み込んだ型かどうかに関係なく、同じようにつなげます。`plugins` には `components` と `process_factories` を並べて書けるので、第 3 章の `increment_process` のような別ファイルの Process とつなぐこともできます。
- 設定ファイルを使わずに、コマンドラインから Component を読み込むこともできます。`-1` を付けると、Component の中のすべての型から、インスタンスを 1 つずつ作ります(名前は第 1 章と同じく「型名 + `0`」になります)。

## まとめ

- Component は、複数の Process・Container・ContainerProcess を 1 つのライブラリにまとめたものです。
- 設定ファイルでは、`plugins` の `components` に Component の名前を 1 つ書くだけで、中の型がすべて読み込まれます。
- インスタンスの作り方、ID、呼び出し方、つなぎ方は、別々のファイルから読み込んだときと同じです。Component は動かし方を変えるものではなく、**配布の単位**です。
