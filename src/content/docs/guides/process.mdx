This example is a Process that just adds 1 to its argument and returns it. The name of the function (or manifest) becomes the Process's type name.

<Tabs syncKey="lang">
<TabItem label="Rust">

```rust
use juiz_sdk::prelude::*;

#[juiz_process]
fn increment_process(arg1: i64) -> JuizResult<Capsule> {
    log::trace!("increment_process({:?}) called", arg1);
    return Ok(jvalue!(arg1 + 1).into());
}
```

A function marked with the `#[juiz_process]` macro becomes the body of the Process.
It can take several arguments, of types such as `i64`, `f64`, `bool`, `String`, `Value` and `Vec<Value>`. Parameter names become the argument names as is.

</TabItem>
<TabItem label="C++">

```cpp
#include "juiz/juiz.h"

juiz::Value manifest() {
    return ProcessManifest{"increment_process_cpp"}
        .add_int_arg("arg1", "test_argument", 1)
        .into_value();
}

std::optional<int64_t> increment_process(juiz::CapsuleMap cm) {
    auto a = cm.get_int("arg1");
    return a + 1;
}

PROCESS_FACTORY(manifest, increment_process);
```

In C++ you write the manifest (the type name and argument definitions) yourself and export it with `PROCESS_FACTORY`.

</TabItem>
<TabItem label="Python">

```python
from juiz import *

@juiz_process
def increment_process(arg1: int = 1) -> int:
    return arg1 + 1
```

Just add the `@juiz_process` decorator to make it a Process. Define your own data types as dataclasses, and convert outputs to dicts with `asdict` before returning them.

</TabItem>
<TabItem label="Haskell">

```haskell
{-# LANGUAGE OverloadedStrings #-}
{-# LANGUAGE TemplateHaskell #-}
module IncrementProcess () where

import Juiz

manifest :: ProcessManifest
manifest = processManifest "increment_process_hs"
  & description "Adds 1 to arg1."
  & addIntArg "arg1" "value to be incremented" 1

increment :: Int64 -> IO Int64
increment arg1 = pure (arg1 + 1)

juizProcess 'increment 'manifest
```

In Haskell, you use hsjuiz, write the manifest (type name and argument definitions) yourself, and expose it with `juizProcess`. Arguments are passed to the function in the order they are added to the manifest.
The result can be `IO r` or a plain `r`. Build it as a shared library with a cabal `foreign-library` (`type: native-shared`, `ghc-options: -threaded`).
For the types you can use and how to return errors, see the [hsjuiz README](https://github.com/OpenJUIZ/juiz/tree/main/bindings/hsjuiz); for setting up a project, see [tutorial chapter 1 (Haskell)](/tutorial/first-process/haskell/).

</TabItem>
</Tabs>

## Running it on its own

Give the built file with `--process`, and instantiate and run it with `-e`.

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
juiz --process target/debug/libincrement_process.so -l rust -e -1 -d
```

</TabItem>
<TabItem label="macOS">

```sh
juiz --process target/debug/libincrement_process.dylib -l rust -e -1 -d
```

</TabItem>
<TabItem label="Windows">

```powershell
juiz --process target/debug/increment_process.dll -l rust -e -1 -d
```

</TabItem>
</Tabs>

- `-l` is the language (`rust` / `cpp` / `python` / `haskell`, default `rust`)
- `-e` instantiates one loaded Process and runs it with its default arguments
- `-1` creates one instance per loaded module
- `-d` starts the HTTP broker after running and keeps waiting
