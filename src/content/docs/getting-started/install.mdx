There are two ways to install the `juiz` command. Pick one based on the languages you use.

| Languages | Install with | Rust toolchain |
| --- | --- | --- |
| Python, C++, Haskell | `pip install juiz-cli` | Not needed |
| Rust (Python, C++ and Haskell can be mixed in) | `cargo install juiz_app` | Needed |

C++ and Haskell components work with either `juiz`. Prepare libjuiz_sdk of the same version as `juiz` (see [C++ and Haskell: libjuiz_sdk](/getting-started/packages/#c-and-haskell-libjuiz_sdk) in Language packages).

## Installing the juiz command

Pick how you install it. The Python notes in [Language packages](/getting-started/packages/) switch to match your choice.

<Tabs syncKey="install">
<TabItem label="Install with pip">

Installing [juiz-cli](https://pypi.org/project/juiz-cli/) from PyPI gives you both the `juiz` command and [pyjuiz](https://pypi.org/project/pyjuiz/) (`import juiz`), the package you write Processes with. No Rust toolchain is needed.

Requirements:

- Python 3.10 or later
- Linux (x86_64, aarch64), macOS (Apple silicon, Intel), or Windows (x86_64)

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install juiz-cli
juiz --help
```

</TabItem>
<TabItem label="macOS">

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install juiz-cli
juiz --help
```

</TabItem>
<TabItem label="Windows">

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install juiz-cli
juiz --help
```

</TabItem>
</Tabs>

The `juiz` command is installed into the venv. Run `juiz` from a terminal where this venv is activated.
pyjuiz is installed along with it, so there is nothing else to install for writing Python Processes.

<Aside type="caution">
The `juiz` installed with pip is built by the juiz CI. It cannot load Rust plugins you build yourself (such as Processes written in Rust), because the compiler versions do not match.
If you also write in Rust, follow "Install with cargo" instead. C++ and Haskell plugins can be loaded.
</Aside>

</TabItem>
<TabItem label="Install with cargo">

Requirements:

- Linux, macOS, or Windows (x86_64)
- Rust 1.81 or later (install with [rustup](https://rustup.rs/))
- On Windows: "Desktop development with C++" from Visual Studio 2022 or Build Tools for Visual Studio 2022 (the linker used by Rust's MSVC toolchain; 2019 has also been confirmed to work)
- For C++ components: CMake and a C++17 compiler
- For Python components as well: Python 3 with development headers (`sudo apt install python3-dev python3-venv` on Ubuntu; on Windows, a Python installed with the python.org installer needs nothing extra)

Install `juiz_app` from crates.io. The same command works in PowerShell on Windows.

```sh
cargo install juiz_app --version 0.0.27 --locked
```

The `juiz` command is installed into `~/.cargo/bin` (`%USERPROFILE%\.cargo\bin` on Windows).

**Using Python Processes too**

To run Python Processes with this `juiz`, add **only** [pyjuiz](https://pypi.org/project/pyjuiz/) from PyPI, at the same version as `juiz`.
The `juiz` command embeds the Python it found at build time, so create the venv with that same Python.

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install pyjuiz==0.0.27
```

</TabItem>
<TabItem label="macOS">

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install pyjuiz==0.0.27
```

</TabItem>
<TabItem label="Windows">

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install pyjuiz==0.0.27
$env:PYTHONPATH = "$PWD\.venv\Lib\site-packages"
```

The last line works around the issue described in the caution below.

</TabItem>
</Tabs>

<Aside type="caution" title="Using cargo's juiz with Python on Windows">
On Windows, a `juiz` installed with cargo cannot load packages (such as pyjuiz) from the activated venv ([juiz#296](https://github.com/OpenJUIZ/juiz/issues/296)). Loading a Python Process fails with `ModuleNotFoundError: No module named 'juiz'`.
In the terminal where you start `juiz`, put the venv's `Lib\site-packages` into the `PYTHONPATH` environment variable. `$PWD` is the current directory, so run this in the directory where you created `.venv`.

```powershell
$env:PYTHONPATH = "$PWD\.venv\Lib\site-packages"
```

The setting is lost when you close the terminal. It is planned to become unnecessary in juiz 0.0.28 and later.
</Aside>

<Aside type="caution">
When you install with cargo, do not install `juiz-cli`. You would end up with two `juiz` commands, and which one runs would depend on the order of your PATH.
</Aside>

</TabItem>
</Tabs>

## What to read next

Once `juiz` is installed, prepare the package for the language you write components in, in [Language packages](/getting-started/packages/) (if you installed with pip and use Python, there is nothing more to install).

## Building from source

To use the development version, clone the repository and build it.

```sh
git clone https://github.com/OpenJUIZ/juiz.git
cd juiz
cargo build
cargo install --path juiz_app
```
