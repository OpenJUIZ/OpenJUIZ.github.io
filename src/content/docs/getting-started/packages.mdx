Once you have installed the `juiz` command in [Installation](/getting-started/install/), prepare the package for the language you write components in. You only need the section for your language.

## Rust

Write components with the [juiz_sdk](https://crates.io/crates/juiz_sdk) crate, built as a shared library.
Use the same juiz_sdk version as the `juiz` you installed with `cargo install juiz_app`. A plugin built with a different version stops with an error when it is loaded.

```toml
[lib]
crate-type = ["cdylib"]

[dependencies]
juiz_sdk = "0.0.27"
```

[Tutorial chapter 1 (Rust)](/tutorial/first-process/rust/) explains `Cargo.toml` line by line.

## Python

Write components with the decorators in [pyjuiz](https://pypi.org/project/pyjuiz/) (`from juiz import juiz_process` and so on).

<Tabs syncKey="install">
<TabItem label="Install with pip">

pyjuiz comes with `juiz-cli`. There is nothing else to install.

</TabItem>
<TabItem label="Install with cargo">

As described in "Using Python Processes too" in [Installation](/getting-started/install/), install only pyjuiz, at the same version as `juiz`.

```sh
pip install pyjuiz==0.0.27
```

</TabItem>
</Tabs>

## C++ and Haskell: libjuiz_sdk

C++ and Haskell components link to libjuiz_sdk, the shared library of C functions that pass values to and from juiz.
Archives of libjuiz_sdk with the headers for each OS and CPU are on [GitHub Releases](https://github.com/OpenJUIZ/juiz/releases) (from 0.0.26).
Use the **same version** as `juiz`. juiz refuses to load a plugin built with a different version of libjuiz_sdk.

The easiest way is `install-juiz-sdk.sh` (`install-juiz-sdk.ps1` on Windows), which detects your OS and CPU. It extracts the archive to `~/.juiz/sdk/<version>` (`%USERPROFILE%\.juiz\sdk\<version>` on Windows).

<Tabs syncKey="platform">
<TabItem label="Linux">

```sh
juiz --version      # e.g. juiz 0.0.27
curl -fsSL https://raw.githubusercontent.com/OpenJUIZ/juiz/main/scripts/install-juiz-sdk.sh | sh -s -- 0.0.27
```

</TabItem>
<TabItem label="macOS">

```sh
juiz --version      # e.g. juiz 0.0.27
curl -fsSL https://raw.githubusercontent.com/OpenJUIZ/juiz/main/scripts/install-juiz-sdk.sh | sh -s -- 0.0.27
```

</TabItem>
<TabItem label="Windows">

Run this in PowerShell. Windows archives are available from 0.0.27.

```powershell
juiz --version      # e.g. juiz 0.0.27
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/OpenJUIZ/juiz/main/scripts/install-juiz-sdk.ps1))) 0.0.27
```

</TabItem>
</Tabs>

The extracted directory contains:

| Path | Contents |
| --- | --- |
| `lib/` | libjuiz_sdk (`.so` on Linux, `.dylib` on macOS) and `pkgconfig/juiz_sdk.pc` for pkg-config. On Windows, the import library `juiz_sdk.dll.lib` used for linking |
| `bin/` | Windows only. The libjuiz_sdk DLL, `juiz_sdk.dll` |
| `lib/cmake/juiz_sdk/` | Settings for CMake's `find_package(juiz_sdk)` (from 0.0.27) |
| `cjuiz/include/` | C headers |
| `cppjuiz/include/` | C++ headers (`juiz/juiz.h`) |

For 0.0.25 and earlier, get the juiz source at the tag of the same version as `juiz` and build libjuiz_sdk with `cargo build --release -p juiz_sdk`.

## C++

From 0.0.27, CMake can use libjuiz_sdk through `find_package`. Point `CMAKE_PREFIX_PATH` (or the `PATHS` of `find_package`) at the extracted directory.

```cmake
find_package(juiz_sdk 0.0.27 EXACT CONFIG REQUIRED)
add_library(my_process SHARED my_process.cpp)
target_link_libraries(my_process PRIVATE juiz_sdk::juiz_sdk)
juiz_sdk_copy_runtime(my_process)   # on Windows, copies juiz_sdk.dll next to the plugin
```

`juiz_sdk::juiz_sdk` also carries the header directories and the C++17 requirement. On Windows, juiz looks for the `juiz_sdk.dll` a plugin uses in the plugin's directory (and in `PATH`), so `juiz_sdk_copy_runtime` copies it there.
[Tutorial chapter 1 (C++)](/tutorial/first-process/cpp/) explains the CMake file line by line.

Without CMake, add `cjuiz/include` and `cppjuiz/include` to the include path, and link to libjuiz_sdk in `lib` (`lib/juiz_sdk.dll.lib` on Windows).
You can also let CMake fetch libjuiz_sdk, as [cmake/Juiz.cmake](https://github.com/OpenJUIZ/juiz_examples_cpp/blob/main/cmake/Juiz.cmake) in the [juiz_examples_cpp](https://github.com/OpenJUIZ/juiz_examples_cpp) examples does.

## Haskell

Write components with [hsjuiz](https://github.com/OpenJUIZ/juiz/tree/main/bindings/hsjuiz). You need GHC 9.4.7 or later and cabal (Linux, macOS; Windows is supported from 0.0.27 and needs GHC 9.6 or later).
hsjuiz is waiting to be published on Hackage, so for now get the juiz source at the tag of the same version as `juiz` and use its `bindings/hsjuiz`. In the `cabal.project` of your package, write where the hsjuiz source and libjuiz_sdk are.

```sh
git clone --depth 1 --branch v0.0.27 https://github.com/OpenJUIZ/juiz.git ~/juiz-0.0.27
```

The commands for Windows are in the "Windows" tab below.

<TabItem label="Windows">

From 0.0.27 you can write components in Haskell on Windows (x86_64) too. You need GHC 9.6 or later (juiz's CI checks it with GHC 9.6.7).

The import library of libjuiz_sdk that Rust builds is named `juiz_sdk.dll.lib`, which GHC's `-ljuiz_sdk` cannot find.
Copy it into a separate directory under the name `juiz_sdk.lib`.

```powershell
git clone --depth 1 --branch v0.0.27 https://github.com/OpenJUIZ/juiz.git $env:USERPROFILE\juiz-0.0.27
mkdir $env:USERPROFILE\.juiz\sdk\0.0.27\import -Force
Copy-Item $env:USERPROFILE\.juiz\sdk\0.0.27\lib\juiz_sdk.dll.lib $env:USERPROFILE\.juiz\sdk\0.0.27\import\juiz_sdk.lib
```

```txt title="cabal.project"
packages: . C:/Users/me/juiz-0.0.27/bindings/hsjuiz

package hsjuiz
  extra-lib-dirs: C:/Users/me/.juiz/sdk/0.0.27/import, C:/Users/me/.juiz/sdk/0.0.27/bin
```

`import` is where `juiz_sdk.lib` for linking is, and `bin` is where GHC loads `juiz_sdk.dll` from when it runs Template Haskell.
Windows has no rpath. juiz looks for the `juiz_sdk.dll` a plugin uses in the plugin's directory (and in `PATH`), so copy `bin\juiz_sdk.dll` next to the DLL you built.

GHC on Windows has no Haskell shared libraries, so the RTS and the packages you depend on are linked statically into the DLL.
In your package's `.cabal`, write `options: standalone` in each `foreign-library`, and pass a `.def` file listing the exported functions with `mod-def-file` (cabal does not accept them in a `common` stanza).

```text title="your-package.cabal (excerpt)"
foreign-library increment_process_hs
    type:             native-shared
    if os(windows)
        options:      standalone
        mod-def-file: increment_process_hs.def
    ...
```

```text title="increment_process_hs.def"
EXPORTS
    juiz_hs_init
    manifest_entry_point
    process_factory_entry_point
```

The library you get is `<name>.dll`, without `lib`. Unlike Linux and macOS, each DLL has its own RTS, so put a Container and its ContainerProcesses into one Component (one DLL) with `juizComponent`.
Also, running a `case` that branches on a value of a type with 8 or more constructors (including `show` from `deriving Show`) is known to crash the process ([issue #262](https://github.com/OpenJUIZ/juiz/issues/262)).
See the ["Windows" section of the hsjuiz README](https://github.com/OpenJUIZ/juiz/tree/main/bindings/hsjuiz#windows) for details.

</TabItem>
</Tabs>

Replace `/home/me`, `/Users/me` or `C:/Users/me` with your home directory (`~` cannot be used in `cabal.project`).
On Linux and macOS, the rpath is needed because GHC loads libjuiz_sdk together with hsjuiz when it runs Template Haskell.
The `build.sh` of the [juiz_examples_haskell](https://github.com/OpenJUIZ/juiz_examples_haskell) examples does everything from getting libjuiz_sdk and hsjuiz to building the examples, so you can also use it as a template.

See the [hsjuiz README](https://github.com/OpenJUIZ/juiz/tree/main/bindings/hsjuiz) for how to write them.

</Aside>
